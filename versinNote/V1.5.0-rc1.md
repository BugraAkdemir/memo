# Memo V1.5.0 Stable — Release Notes

Memo (Local LLM Memory) reaches **V1.5.0 Stable** with a massive performance overhaul, an ultra-fast memory architecture, and dynamic GPU acceleration. This release dramatically improves both the runtime speed and hardware compatibility of the local AI engine.

---

## 🚀 Highlights & New Features

### 1. Ultra-Fast Separated Memory & RAM Cache
*   **RAM-Based Vector Index (`LoadCache`):** No more reading heavy files from disk on every memory search. At startup, the ID and vector data of all memories are pre-loaded into a RAM index.
*   **Parallel Semantic Search:** Semantic search now runs directly in RAM using a concurrent worker pool that fully utilizes all CPU cores — results arrive in **milliseconds**, not seconds.
*   **Hybrid Disk/RAM Retrieval:** The vector search happens at RAM speed; only the full content of the closest matching memories is then read from disk. This makes memory query performance up to **10× faster**.
*   **Safe RAM/Disk Consistency:** Adding, deleting, and clearing memories keeps the in-memory index and the on-disk store in sync at all times, without data corruption.

### 2. Smart GPU Acceleration & Dynamic Installer (1-Click Upgrade)
*   **Dynamic Hardware Detection (`HasGPUSupport`):** NVIDIA (CUDA) and AMD (ROCm/Vulkan) GPUs are detected automatically. The installer also checks whether the currently installed binaries actually support the detected GPU.
*   **1-Click GPU Upgrade:** If a capable GPU is found but the installed binaries are CPU-only, an elegant installer screen appears and downloads the optimal GPU binary with a single click.
*   **Zero-Setup Offline CPU Fallback:** On machines without a discrete GPU, the app launches instantly using the bundled CPU binary — no internet connection required.
*   **"Use CPU" Bypass Support:** Users who have a GPU but are offline or simply prefer CPU mode can skip GPU installation. A bypass file (`data/.force_cpu`) is written in the background, and all future starts will skip the GPU check automatically.

### 3. Advanced Latency Logging & Observability
*   Millisecond-precision latency logs have been added at every critical stage so performance bottlenecks are immediately visible:
    *   Memory cold-start cache load time.
    *   Retrieval breakdown: embedding, RAM search, and disk read times.
    *   Chat message build time, history length, and memory count.
    *   LLM stream time-to-first-token, ready time, and total stream completion time.
    *   Async background memory save time.

### 4. Customisable Advanced Memory Settings
*   **Top K & Minimum Similarity:** The `top_k` (search breadth) and `min_similarity` (relevance threshold) parameters are now exposed on the REST API and in the Flutter UI.
*   **Settings › Memory Tab:** Adjust these parameters live from the new Memory tab in the Settings dialog — changes are saved instantly to `config/config.yaml`.

## 🛠️ Technical Improvements & Stability

*   Fixed a crash (`panic`) that occurred when an in-memory entry no longer had a matching file on disk — replaced with safe error logging.
*   `internal/memory` and all Go backend packages are now fully `gofmt`-compliant; all tests (`go test ./...`) pass cleanly.
*   `build_releases.sh` updated to handle the new library-check and bypass mechanisms, producing correct AppImage, tar.gz, and .deb artifacts.

## 🐛 Bug Fixes & Stability Improvements

### Llama.cpp Installer: Linux/macOS Fix
*   **`.tar.gz` Archive Support:** The installer now correctly downloads the official `.tar.gz` packages from the Llama.cpp GitHub releases for Linux and macOS. Previously, the installer only looked for `.zip` files; when none were found, it fell back to a 5–10 minute `cmake` source compilation. With this fix, installation completes in **seconds**.
*   **GPU-Aware Installer UI:** The installation dialog now reads the system's GPU status in real time. On CPU-only machines, the misleading "Install for GPU (Recommended)" button is replaced with a plain **"Download & Install Engine"** label. The "Use CPU Instead" option only appears when a GPU is actually detected.
*   **Installation Timeout Fix:** On machines where the source-build fallback was triggered, the Flutter client was crashing with `DioException [receive timeout]` after 2 minutes. The install request timeout has been raised to **15 minutes**, fully covering even the worst-case compilation scenario.
*   **macOS Support:** Added a macOS platform profile to the installer asset picker; Apple Silicon and Intel Macs can now download the correct pre-built binary on first run.
