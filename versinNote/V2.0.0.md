# Memo V2.0.0 — Release Notes

**"Bundled Engine & GPU Mode Control"**

Memo V2.0.0 is a **Major Release** that fundamentally changes the application's engine architecture. The internet-dependent "download-on-demand" system has been replaced with a **Plug-and-Play (Bundled Engine)** architecture that ships all hardware variants (CPU / NVIDIA / AMD) inside the package. From the very first launch — without any internet connection — the AI engine is ready to go.

---

## 🏗️ Architectural Change: Bundled Llama Engine

> The **download-on-demand** model from V1.5.0 has been completely abandoned.

### Previous System (V1.5.0)
- llama.cpp binaries were downloaded from GitHub on first launch.
- Internet speed, GitHub availability, and library symlink errors caused critical failures.
- Only a CPU-only binary was bundled; GPU support required an additional download.

### New System (V2.0.0)
- The application package now ships with **3 separate engine sets** (CPU, NVIDIA/CUDA, AMD/ROCm) embedded:
  ```
  binaries/
  ├── linux/
  │   ├── cpu/llama-server
  │   ├── nvidia/llama-server
  │   └── amd/llama-server
  └── windows/
      ├── cpu/llama-server.exe
      ├── nvidia/llama-server.exe
      └── amd/llama-server.exe
  ```
- **100% Offline Operation:** No internet required from the very first install.
- **Guaranteed Compatibility:** Pre-tested binaries for each platform minimize "doesn't work on my machine" scenarios.
- **Increased Package Size:** Package size has grown from ~100 MB to ~700 MB – 1 GB. This is a deliberate trade-off.

## 🚀 Highlights & New Features

### 1. Engine Mode Selection — New UI
*   A new **"Engine Mode"** dropdown has been added to the **Settings → Llama** tab.
*   Available modes:
    | Mode | Behavior |
    |------|----------|
    | **Automatic (Recommended)** | Detects system hardware and selects the optimal binary. |
    | **CPU Only** | Forces zero GPU layers and uses the CPU-only binary. |
    | **NVIDIA (CUDA)** | Forces the CUDA-enabled NVIDIA binary. |
    | **AMD (ROCm/Vulkan)** | Forces the ROCm/Vulkan-enabled AMD binary. |
*   Mode changes are instantly sent to the backend via `PUT /api/models/config` and persisted to `config.yaml`.
*   The running embedding server is automatically stopped and restarted with the new mode — no app restart required.

### 2. New Config API Endpoints
*   `GET /api/models/config` — Returns the current Llama configuration (engine_mode, binary_path, port, etc.).
*   `PUT /api/models/config` — Updates the engine mode and other Llama settings.
*   A new `UpdateLlamaConfig()` bridge function was added to the backend; config changes are atomically written to disk.

### 3. Synchronous Model Loading
*   **Old behavior (V1.5.0):** `StartLocalModel` ran in a fire-and-forget goroutine. Since the Flutter event system was disabled, model loading status (loading/ready/error) never reached the UI — causing silent failures.
*   **New behavior (V2.0.0):** Model loading is now **synchronous**. The HTTP request blocks until the model is ready (max 3 minutes). Success or failure is returned directly via the HTTP response.
*   The UI can now reliably display model loading status: success means running, failure returns a meaningful, localized error message to the user.

### 4. Redesigned Model Store UI
*   **HuggingFace Search Cards** have been completely redesigned:
    - Like count, tags, and download count are now visually enriched.
    - Gradient backgrounds, shadows (`shadowMd`), and hover effects added.
    - "View Files" button renamed to "Explore Files" with modernized icons.
*   **Download Progress Card** has been rewritten from scratch:
    - Human-readable size formatting (`_formatBytes`): displays `1.2 GB / 4.7 GB` style output.
    - Gradient background, large icon, and prominent filename for a premium look.
    - Local model list auto-refreshes when download completes (`ref.invalidate(localModelsProvider)`).
*   **Engine Guard Integration:** The local model "Start" button is automatically disabled if the Llama engine is not installed (`!installed ? null : onPressed`). The user must install the engine first.

### 5. System Hardware Status Panel
*   A new **"System Hardware Status"** info card has been added to the Settings → Llama screen.
*   Detected GPU name and type are displayed in real time.
*   If no GPU is detected, a "CPU only detected" notice is shown.

## 🛠️ Technical Improvements & Infrastructure

### Binary Resolution Engine (`resolveBinary`) — Completely Rewritten
*   The resolution priority order is now:
    1. Selected mode (`binaries/{os}/{mode}/llama-server`) — direct target.
    2. Configured path (`config.yaml → binary_path`).
    3. Bundled auto-scan: searched in `amd → nvidia → cpu → bin/` order.
    4. System PATH (`exec.LookPath`).
*   When a bundled binary is detected, dynamic GPU checks are skipped — binary compatibility is the bundler's responsibility.

### Installer Improvements (`installer.go`)
*   **Architecture awareness:** `GOARCH` (`x64`) filter added to asset selection. Prevents downloading binaries for the wrong architecture.
*   **Extended fallback chain:** Platform + architecture + GPU preference → platform + architecture → platform (last resort).
*   **Symlink support:** Symbolic links are now correctly handled during `.tar.gz` extraction (especially the `libllama.so → libllama.so.xxxx` chain).

### Embedding Server Management
*   The existing running instance is automatically stopped before starting a new embedding server. Port collisions are prevented.
*   `WaitReady` timeout increased from 60 seconds to **120 seconds** (for large embedding models).
*   `--pooling mean` parameter removed — relies on llama.cpp's default behavior.

### Config Structure (`config.yaml` / `config.go`)
*   New field: `engine_mode` (default: `"auto"`) — accepts `"auto"`, `"cpu"`, `"nvidia"`, `"amd"`.
*   `binary_path` now defaults to empty — the bundled system handles automatic resolution.
*   New field: `max_history` — controls chat history length (default: 20).

### Packaging Scripts — Restructured
*   **`package_linux.sh`** and **`package_windows.sh`**: Now copy from `binaries/{platform}/` instead of `data/bin/`.
*   **`build_releases.sh`**: First-run logic updated from `data/bin/llama-server` check to `binaries/` directory check. AppImage, .deb, and .tar.gz packages correctly carry the new structure.
*   **[NEW] `download_binaries.sh`**: Automation script added for developer convenience — downloads all platform binaries from GitHub in a single command.
*   `chmod +x` is automatically applied to engine binaries.

### Error Messages (UX)
*   When the Llama binary is not found, a meaningful localized error message is returned:
    > *"Llama.cpp engine (llama-server) not found. Please make sure the engine is installed or check the path in Settings → Llama."*
*   On model loading timeout:
    > *"Model loading timed out (3 min)."*

## ⚡ V1.5.0 → V2.0.0 Migration Summary

| Feature | V1.5.0 | V2.0.0 |
|---------|--------|--------|
| Engine Distribution | Download-on-demand | **Bundled (Plug-and-Play)** |
| First Launch | Internet required | **100% Offline** |
| GPU Mode | Auto-detect + fallback | **User-selectable** (Auto/CPU/NVIDIA/AMD) |
| Model Loading | Async (silent failures) | **Synchronous (reliable response)** |
| Binary Resolution | `data/bin/` single path | **Smart multi-path scanning** |
| Package Size | ~100 MB | **~700 MB – 1 GB** |
| Config API | None | **GET/PUT /api/models/config** |
| Engine Mode Persistence | `.force_cpu` file | **config.yaml → engine_mode** |
| Embedding Timeout | 60 seconds | **120 seconds** |
| Error Messages | English / technical | **Localized / user-friendly** |
