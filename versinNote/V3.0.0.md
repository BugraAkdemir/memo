# V3.0.0 — Sürüm Notları

## 🔧 Düzeltmeler

### K1 — Yetim SSE Bağlantıları (Orphaned SSE Streams)
İstemci bağlantıyı kestiğinde LLM'in gereksiz yere çalışmaya devam etmesi sorunu çözüldü.

- **Değişen Dosyalar:**
  - `internal/webserver/bridge.go` — `FullBridge` stream metodlarına `ctx context.Context` parametresi eklendi
  - `internal/webserver/handlers_flutter.go` — `handleSendStream` artık `r.Context()`'i zincire iletiyor
  - `app.go` — `SendMessageStream`, `SendMessageWithImageStream`, `SendMessageWithFileStream`, `handleIncognitoStream` artık `ctx` parametresi alıp `callLLMStream`'e iletiyor
- **Nasıl Çalışır:** İstemci kopunca HTTP context cancel oluyor → `streamCtx` (child) iptal oluyor → `ChatCompletionStream` HTTP isteği iptal ediliyor → goroutine doğal olarak sonlanıyor
- **Etki:** GPU/CPU kaynağı boşa harcanmıyor, düşük donanımda orphaned stream yeni istekleri bloke etmiyor

### K2 — Engine Modu Değişince Tüm Config Sıfırlanıyor
Kısmi JSON body (`{"engine_mode": "cpu"}`) tüm `LlamaConfig` struct'ını sıfırlaması sorunu çözüldü.

- **Değişen Dosyalar:**
  - `app.go` — `UpdateLlamaConfig` artık tüm struct'ı replace etmek yerine field-by-field merge yapıyor
- **Nasıl Çalışır:** Sadece non-zero değerler mevcut config'e yazılıyor. Kısmi update sadece ilgili alanı değiştiriyor, diğer ayarlar korunuyor
- **Etki:** Engine mode değiştirince binary_path, port, ctx_size gibi ayarlar sıfırlanmıyor

### K3 — `/api/image` ile Keyfi Dosya Okuma
`/api/image?path=...` endpoint'inde path sanitization olmaması, `/etc/passwd`, `~/.ssh/id_rsa` gibi keyfi dosyaların okunabilmesi sorunu çözüldü.

- **Değişen Dosyalar:**
  - `internal/webserver/handlers_flutter.go` — `handleImage`'e Layer 1 path doğrulaması eklendi (`..` ve absolute path reddedilir)
  - `app.go` — `GetImageBase64`'e Layer 2 whitelist kontrolü eklendi (sadece `data/` dizini altındaki yollara izin verilir)
- **Nasıl Çalışır:** Handler seviyesinde `..` traversal ve absolute path engellenir. `GetImageBase64` seviyesinde `filepath.Abs` + `filepath.EvalSymlinks` ile path resolve edilip `data/` dizini prefix kontrolü yapılır. Symlink saldırıları da engellenir.
- **Etki:** Remote access açık olsa bile sistem dosyaları okunamaz. Kullanılmayan bir endpoint olduğu için hiçbir özellik etkilenmez.

### K4 — Remote Access'te Auth Yok, CORS Açık
Remote access özelliği komple devre dışı bırakıldı. Flutter'da da "Yapım aşamasında..." olarak duran bu özellik, ileride düzgün auth + CORS implementasyonu ile tekrar eklenecek.

- **Değişen Dosyalar:**
  - `internal/webserver/server.go` — `Start()` anında hata döndürür. CORS `*` yerine `Origin` header'ını yankılar
  - `app.go` — `SetRemoteAccess` enable edilemez. Startup'ta remote server başlatılmaz
- **Etki:** Remote access tamamen kapalı. Localhost Flutter API'si etkilenmez.

### K5 — `a.client` / `a.embeddingClient` Race Condition
`App` struct'ına `clientMu sync.RWMutex` eklendi. `a.client` ve `a.embeddingClient` tüm yazma/okuma işlemleri artık bu mutex ile korunuyor.

- **Değişen Dosyalar:**
  - `app.go` — `clientMu` field'ı eklendi, 5 yazma yeri Lock/Unlock, 6 okuma yeri RLock/RUnlock ile korundu
- **Nasıl Çalışır:** Client atanırken Lock alınır. Client okunurken RLock alınır, pointer kopyalanır, kopya üzerinden işlem yapılır. Race condition ve nil-pointer panic önlenir.
- **Etki:** Model start/stop sırasında eşzamanlı istekler güvenli. Nil-client panic riski sıfır.

### K6 — `saveMemoryAsync` RLock→Lock Deadlock
Lock+goroutine pattern'i channel-based worker ile değiştirildi. Tek bir `memorySaveWorker` goroutine kanaldan okur, `storeMu.Lock()` alır, kaydeder. RLock→Lock geçişi tamamen kalktı.

- **Değişen Dosyalar:**
  - `app.go` — `saveTask` struct, `memorySaveCh` channel, `memorySaveWorker`, `saveMemorySync` eklendi. `saveMemoryAsync` sadece kanala yazar
- **Nasıl Çalışır:** `saveMemoryAsync` → `memorySaveCh` → `memorySaveWorker` (tek goroutine) → Lock → SaveInteraction. Kanal 64 kapasiteli, dolarsa drop + log.
- **Etki:** Deadlock riski sıfır. Hafıza kaydetme sıralı ve güvenli.

### K7 — Mesaj Başına AnimationController (UI Jank)
Her `_MessageBubble` widget'ı kendi `AnimationController`'ını oluşturup `FadeTransition` + `SlideTransition` yapıyordu. 50+ mesajda severe frame drop'a neden oluyordu.

- **Değişen Dosyalar:**
  - `frontend/lib/widgets/chat_message_list.dart` — `_MessageBubble`'dan `SingleTickerProviderStateMixin`, `AnimationController`, `FadeTransition`, `SlideTransition` tamamen kaldırıldı
- **Etki:** Mesaj sayısından bağımsız akıcı scroll. Streaming sırasında token başına frame drop yok.

### Y13 — Oturum Kimliği Çakışması (Session ID Collision)
Oturum kimlikleri UUID'in ilk 8 hex karakterine kırpıldığı için ~10^5 oturumda %1 çakışma riski vardı. Çakışma durumunda eski oturum sessizce siliniyordu.

- **Değişen Dosyalar:**
  - `internal/sessions/sessions.go:68` — `uuid.New().String()[:8]` → `uuid.New().String()`
- **Etki:** Sohbet geçmişi kaybı riski sıfırlandı. Tam UUID (36 karakter) kullanılıyor.

### Y6 — `hash2hex` Çakışma Riski (Memory File Hash Collision)
Hafıza dosya adları SHA-256'nın sadece ilk 4 baytı (32 bit) kullanılarak oluşturuluyordu. ~2^16 girişte %50 çakışma olasılığı vardı.

- **Değişen Dosyalar:**
  - `internal/memory/store.go:344` — `hash[:4]` → `hash[:8]`
- **Etki:** Çakışma olasılığı %50'den ihmal edilebilir seviyeye düştü. Hafıza kaybı riski ortadan kalktı.

### Y2 — Config Dosyası İzinleri (World-Readable Config)
`config.yaml` 0644 izniyle yazıldığı için OAuth sırları ve şifreleme passphrase'i tüm yerel kullanıcılar tarafından okunabiliyordu.

- **Değişen Dosyalar:**
  - `internal/config/config.go:178` — `0644` → `0600`
- **Etki:** Config dosyası artık sadece dosya sahibi tarafından okunabilir. Multi-user sistemlerde sır sızıntısı önlendi.

### Y8 — İndirme Hatalarında Temp Dosya Sızıntısı (Temp File Leak)
İndirme başarısız olduğunda (HTTP hatası, ağ zaman aşımı) `.downloading` geçici dosyası diske süresiz olarak yazılıp temizlenmiyordu.

- **Değişen Dosyalar:**
  - `internal/modelstore/modelstore.go:237-243` — `os.Remove(tmpPath)` koşulludan koşulsuza çıkarıldı
- **Etki:** Temp dosya birikmesi önlendi. Her çıkış yolunda temizlik garanti altında.

### Y9 — `extractTarGzToBin` Dosya Tanıtıcı Sızıntısı (FD Leak)
Tar çıkarma döngüsünde `out.Close()` manuel çağrıldığı ve defer edilmediği için `io.Copy` hatasında dosya tanıtıcısı sızdırılıyordu.

- **Değişen Dosyalar:**
  - `internal/llama/installer.go` — Yeni `extractFile()` fonksiyonu eklendi, `defer out.Close()` ile FD güvenliği sağlandı
- **Etki:** Kısmen bozuk arşivlerde dosya tanıtıcı tükenmesi önlendi.

### Y12 — `Shutdown` Zaman Aşımı Yok (Shutdown Can Block Indefinitely)
Sunucu kapanırken `context.Background()` kullanıldığı için takılı bir HTTP handler'ı varsa kapanma sonsuza kadar bekliyordu.

- **Değişen Dosyalar:**
  - `internal/webserver/server.go:177` — `context.Background()` → `context.WithTimeout(10*time.Second)`
- **Etki:** Uygulama kapanırken 10 saniyeden fazla donmaz. Stream aktif olsa bile güvenli kapanma.

### Y1 — SSE Goroutine Sızıntısı (Goroutine Leak on SSE Disconnection)
İstemci bağlantıyı kestiğinde `processSSEStream` goroutine'i ve LLM HTTP isteği tamamlanana kadar çalışmaya devam ediyor, kaynak sızdırıyordu.

- **Değişen Dosyalar:**
  - `internal/api/streaming.go` — `processSSEStream` artık `ctx context.Context` parametresi alıyor. Context iptalinde body'i kapatan watcher goroutine eklendi
  - `internal/api/client.go` — `ChatCompletionStream` context'i `processSSEStream`'e iletiyor
- **Etki:** İstemci kopunca goroutine ve HTTP bağlantısı saniyeler içinde temizlenir. Kaynak sızıntısı olmaz.

### Y5 — `buildMessages` Oturum Geçmişini Mutasyona Uğratıyor (Session History Mutation)
`buildMessages` içinde sistem prompt enjeksiyonu sırasında `history` slice'ı mutasyona uğruyor, her istekte sistem prompt'u ikiye katlanıyordu.

- **Değişen Dosyalar:**
  - `app.go:1358` — `history = append([]api.Message{}, history...)` savunma amaçlı kopya eklendi
- **Etki:** Sistem prompt'u her istekte tek sefer enjekte edilir. Context taşması ve model karışıklığı önlendi.

### Y7 — `monitor()` Race Condition (Nil-Pointer Panic)
`monitor()` goroutine'i `s.cmd`'ye lock dışında erişiyordu. `Stop()` ile `s.cmd = nil` arasındaki yarışta nil-pointer panik mümkündü.

- **Değişen Dosyalar:**
  - `internal/llama/llama.go:271-302` — Nil kontrolü lock içinde yapılıp local kopyaya alındı. `Wait()` local kopya üzerinden çağrılıyor
- **Etki:** Hızlı start/stop döngülerinde nadir görülen nil-pointer panik riski sıfırlandı.

### Y10 — `nvidia-smi` Hataları Sessiz Geçiliyor (Silent GPU Detection Failures)
`nvidia-smi` çağrıları başarısız olduğunda hatalar loglanmıyor, kullanıcı neden GPU kullanılamadığını göremiyordu.

- **Değişen Dosyalar:**
  - `internal/llama/gpu.go:62-101` — Tüm `nvidia-smi` hata noktalarına `log.Printf` eklendi (binary bulunamazsa, name/VRAM sorgusu başarısız olursa, VRAM parse edilemezse)
- **Etki:** GPU algılaması başarısız olduğunda kullanıcı log'dan sebebini görebilir. Sessiz CPU düşüşü artık görünür.

### Y15 — Backend Bağlantı Hatasında "Kurulu" Gösteriliyor (Connection Error Shows Installed)
Backend ulaşılamaz olduğunda `llamaInstalledProvider` `connectionError`'da `true` döndürüyor, kullanıcı kurulum ekranını göremiyordu.

- **Değişen Dosyalar:**
  - `frontend/lib/providers/models_provider.dart:97-104` — `connectionError` özel durumu kaldırıldı, tüm hatalar `false` döndürür
- **Etki:** Backend düştüğünde kullanıcı kurulum ekranını görür ve işlemi tetikleyebilir.
