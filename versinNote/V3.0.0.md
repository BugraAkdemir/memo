# V3.0.0 — Sürüm Notları

## 🔧 Düzeltmeler

### K1 — Yetim SSE Bağlantıları (Orphaned SSE Streams)
İstemci bağlantıyı kestiğinde LLM'in gereksiz yere çalışmaya devam etmesi sorunu çözüldü.

- **Değişen Dosyalar:**
  - `internal/webserver/bridge.go` — `FullBridge` stream metodlarına `ctx context.Context` parametresi eklendi
  - `internal/webserver/handlers_flutter.go` — `handleSendStream` artık `r.Context()`'i zincire iletiyor
  - `app.go` — `SendMessageStream`, `SendMessageWithImageStream`, `SendMessageWithFileStream`, `handleIncognitoStream` artık `ctx` parametresi alıp `callLLMStream`'e iletiyor
- **Nasıl Çalışır:** İstemci kopunca HTTP context cancel oluyor → `streamCtx` (child) iptal oluyor → `ChatCompletionStream` HTTP isteği iptal ediliyor → goroutine doğal olarak sonlanıyor
- **Etki:** GPU/CPU kaynağı boşa harcanmıyor, düşük donanımda orphaned stream yeni istekleri bloke etmiyor

### K2 — Engine Modu Değişince Tüm Config Sıfırlanıyor
Kısmi JSON body (`{"engine_mode": "cpu"}`) tüm `LlamaConfig` struct'ını sıfırlaması sorunu çözüldü.

- **Değişen Dosyalar:**
  - `app.go` — `UpdateLlamaConfig` artık tüm struct'ı replace etmek yerine field-by-field merge yapıyor
- **Nasıl Çalışır:** Sadece non-zero değerler mevcut config'e yazılıyor. Kısmi update sadece ilgili alanı değiştiriyor, diğer ayarlar korunuyor
- **Etki:** Engine mode değiştirince binary_path, port, ctx_size gibi ayarlar sıfırlanmıyor

### K3 — `/api/image` ile Keyfi Dosya Okuma
`/api/image?path=...` endpoint'inde path sanitization olmaması, `/etc/passwd`, `~/.ssh/id_rsa` gibi keyfi dosyaların okunabilmesi sorunu çözüldü.

- **Değişen Dosyalar:**
  - `internal/webserver/handlers_flutter.go` — `handleImage`'e Layer 1 path doğrulaması eklendi (`..` ve absolute path reddedilir)
  - `app.go` — `GetImageBase64`'e Layer 2 whitelist kontrolü eklendi (sadece `data/` dizini altındaki yollara izin verilir)
- **Nasıl Çalışır:** Handler seviyesinde `..` traversal ve absolute path engellenir. `GetImageBase64` seviyesinde `filepath.Abs` + `filepath.EvalSymlinks` ile path resolve edilip `data/` dizini prefix kontrolü yapılır. Symlink saldırıları da engellenir.
- **Etki:** Remote access açık olsa bile sistem dosyaları okunamaz. Kullanılmayan bir endpoint olduğu için hiçbir özellik etkilenmez.

### K4 — Remote Access'te Auth Yok, CORS Açık
Remote access özelliği komple devre dışı bırakıldı. Flutter'da da "Yapım aşamasında..." olarak duran bu özellik, ileride düzgün auth + CORS implementasyonu ile tekrar eklenecek.

- **Değişen Dosyalar:**
  - `internal/webserver/server.go` — `Start()` anında hata döndürür. CORS `*` yerine `Origin` header'ını yankılar
  - `app.go` — `SetRemoteAccess` enable edilemez. Startup'ta remote server başlatılmaz
- **Etki:** Remote access tamamen kapalı. Localhost Flutter API'si etkilenmez.

### K5 — `a.client` / `a.embeddingClient` Race Condition
`App` struct'ına `clientMu sync.RWMutex` eklendi. `a.client` ve `a.embeddingClient` tüm yazma/okuma işlemleri artık bu mutex ile korunuyor.

- **Değişen Dosyalar:**
  - `app.go` — `clientMu` field'ı eklendi, 5 yazma yeri Lock/Unlock, 6 okuma yeri RLock/RUnlock ile korundu
- **Nasıl Çalışır:** Client atanırken Lock alınır. Client okunurken RLock alınır, pointer kopyalanır, kopya üzerinden işlem yapılır. Race condition ve nil-pointer panic önlenir.
- **Etki:** Model start/stop sırasında eşzamanlı istekler güvenli. Nil-client panic riski sıfır.

### K6 — `saveMemoryAsync` RLock→Lock Deadlock
Lock+goroutine pattern'i channel-based worker ile değiştirildi. Tek bir `memorySaveWorker` goroutine kanaldan okur, `storeMu.Lock()` alır, kaydeder. RLock→Lock geçişi tamamen kalktı.

- **Değişen Dosyalar:**
  - `app.go` — `saveTask` struct, `memorySaveCh` channel, `memorySaveWorker`, `saveMemorySync` eklendi. `saveMemoryAsync` sadece kanala yazar
- **Nasıl Çalışır:** `saveMemoryAsync` → `memorySaveCh` → `memorySaveWorker` (tek goroutine) → Lock → SaveInteraction. Kanal 64 kapasiteli, dolarsa drop + log.
- **Etki:** Deadlock riski sıfır. Hafıza kaydetme sıralı ve güvenli.
