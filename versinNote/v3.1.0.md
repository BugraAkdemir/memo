# Memo v3.1.0 — What's New

> A major release: redesigned interface, smarter model discovery, WhatsApp integration, mobile companion, and much more.

## The Big Picture

This release focuses on two things above all else: **making Memo feel polished and easy to use**, and **making local AI actually work well** — without needing to be a developer to figure it out.

### Interface Redesigned From Scratch
The entire desktop UI has been rebuilt. The layout, colors, typography, and spacing have all been rethought from the ground up. Everything is cleaner, more intentional, and easier to navigate.

### "Pewter Study" Dark Theme
A new default dark theme that's easier on the eyes during long sessions — warm neutrals, clear contrast, no harsh whites.

## Model Store — Completely Rebuilt

The model discovery and download experience has been completely redesigned to work like LM Studio.

### Two-Panel Layout
The Model Store is now split into two panels: a model list on the left, and a rich detail view on the right. No more scrolling through walls of text to find what you need.

### Model Logos
Each model in the list now shows the real logo of the company that made it — Google, Microsoft, Qwen/Alibaba, nomic, and others. The logo is fetched automatically from HuggingFace.

### Only Official Models in "Recommended"
The curated model list now exclusively shows models published by the original creators — not third-party re-uploads or community forks. You'll see:
- **Gemma 3 4B & 12B** — Google's official GGUF release
- **Qwen 3 8B** — Qwen's latest model (official)
- **Qwen 2.5 7B, 14B, Coder 7B** — Qwen official releases
- **Phi-3 mini** — Microsoft official
- **Nomic Embed v1.5** — for memory/RAG

### Download Options That Make Sense
Instead of raw file names like `Q4_K_M`, download options now show plain-language quality labels:
- **Balanced quality** — best for most computers
- **High quality** — if you have more RAM/VRAM
- **Smallest size** — for tight hardware

### Hardware Fit Badges
Every download option shows whether it will run well on your machine:
- **✓ Fits** — will run fast
- **~ CPU OK** — will run, but slower (CPU offload)
- **× Too large** — may not fit in memory

### Filter & Sort
Find what you need faster with filters for model size (1–8B, 8–14B, 14B+) and capability (Tools, Vision, Code), plus sorting by download count or model size.

### Capability Tags
Each model shows icons for what it can do:
- 🔧 **Tool Use** — can use Agent mode and run tasks
- 👁 **Vision** — can understand images
- `</>` **Code** — specialized for programming

### README & Author Info
The detail panel shows the model's full README from HuggingFace, plus a "More from this author" section so you can explore related models.

## Agent Mode

### Stable Tool Use with Local Models
Agent mode (where Memo can browse files, run commands, write code, and take actions autonomously) now works reliably with local models. Memo automatically detects whether a loaded model supports tool calling — from the model's HuggingFace metadata, or by recognizing the model family.

### Agent Pipeline — Context Propagation
Tool execution now respects cancellation context. Running commands (`run_command`) use the pipeline's context instead of `context.Background()`. When the user cancels a request, running tools stop immediately instead of hanging for the full timeout. All 12+ built-in tools accept `context.Context` as their first parameter (`pipeline.go`, `command.go`, `file.go`, `edit.go`, `search.go`, `whatsapp.go`).

### Agent Pipeline — Per-Tool Timeout
Every tool execution enforces a 60-second hard cap via `DefaultToolTimeout` (`tools/command.go`). Combined with the pipeline's own 20-iteration limit, the agent cannot hang indefinitely on any single operation.

### Agent Sandbox — Symlink Protection
Sandbox path validation (`sandbox.go`) now resolves symlinks with `filepath.EvalSymlinks` before checking path boundaries. A symlink inside the project pointing to `/etc/` or other protected paths is no longer accepted.

### Permission Dialog — Instant Response
The permission dialog no longer requires a 2-second wait or double-click. "İzin Ver" button is immediately active. New "Oturum Boyunca İzin Ver" option allows the tool to run without further prompts for the rest of the session. 60-second auto-deny timeout prevents orphaned permission waits (`permission_dialog.dart`, `executor.go`).

### Agent UI — Clean Status Line
Raw JSON tool arguments (`{"path": "main.go"}`) no longer leak into chat messages. Instead of one card per tool call, the streaming bubble shows a **single animated line** that updates as tools execute: "Dosya işleniyor..." → "Dosya tamam ✅". Completed actions appear as compact badges: `[Dosya okudu 120ms]`. The agent chat feels similar to Claude Code — minimal, informative, non-technical (`chat_message_list.dart`, `agent_chat_card.dart`).

### Agent Event Consolidation
Consecutive `tool_executing` events are consolidated in the provider — only the current action is shown, not a growing list. `EventToolExecuting` no longer includes raw args in the payload (`pipeline.go`, `chat_provider.dart`).

### Command Output Truncation Fixed
`run_command` output truncation now uses proportional truncation (stdout/stderr combined 10MB limit) instead of separate 5MB caps. Previously, 6MB stdout + 1MB stderr would only truncate stdout incorrectly (`command.go`).

### WriteFile Size Limit
`WriteFile` now enforces a 10MB content limit in addition to the existing 1024-byte-to-token estimate fix (`file.go`).

## Skill System (opencode-compatible)

Memo now supports opencode-style skills — markdown files that inject instructions and tools into the agent pipeline.

### How It Works
Skills are `SKILL.md` files placed in `data/skills/<skill-name>/` with YAML front matter + Markdown instructions. When a skill is active, its instructions are appended to the system prompt and any tools it defines are registered with the agent's tool registry.

### Skill Format (Two Styles)
- **opencode style** — YAML front matter (name, description, danger_level, tools) followed by Markdown body instructions
- **Single-file style** — instructions field in YAML front matter, no body needed

### Backend Architecture
New `internal/skill/` package with three files:
- `types.go` — `SkillDefinition`, `SkillManifest`, `SkillTool`, `DangerLevel` types
- `loader.go` — `ParseSkill()`, `DiscoverSkills()`, `LoadSkill()` — reads SKILL.md files
- `manager.go` — `Manager` struct with `Discover()`, `Install()`, `Remove()`, `SetActive()`, `ActiveInstructions()`

### Chat Commands
| Command | Action |
|---------|--------|
| `/skill` | List all installed skills |
| `/skill:on <name>` | Activate a skill |
| `/skill:off <name>` | Deactivate a skill |
| `/skill:off` | Deactivate all |
| `/skill install <path>` | Install from local path |
| `/skill remove <name>` | Uninstall a skill |

### API Endpoints
| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/api/skills/list` | List installed skills |
| `GET` | `/api/skills/get/{name}` | Get skill details |
| `POST` | `/api/skills/install` | Install from path |
| `DELETE` | `/api/skills/remove/{name}` | Remove skill |
| `PUT` | `/api/skills/active` | Set active skills |
| `GET` | `/api/skills/active-list` | Get active skills |

### Frontend
- `/skill` appears in the slash-command popup
- `🧩 Skills` tab in Settings with list/toggle/install/remove UI
- Dedicated `SkillConfigDialog` for full management
- Riverpod `skillListProvider` for reactive state

### Orchestra Integration
Active skill instructions are injected into orchestra conversation context via `buildActiveSkillPrompt()` in `app_skill.go`. The `callAgentWithOrchestra` flow now includes skill instructions.

### Token Estimation
Orchestra mode now uses word-based `estimateTokens()` instead of the inaccurate `len(text) / 4` heuristic, providing better token counts for Turkish and code-heavy content.
