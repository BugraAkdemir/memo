# v3.1.0 — Memory, WhatsApp, Mobile Companion & Remote Access

## Highlights

- **SQLite + sqlite-vec** replaces chromem-go for vector storage (ANN index via vec0)
- **Cross-mode**: external API provider chat + local embedding model run independently
- **WhatsApp integration** — QR pairing, bidirectional messaging, contact resolution, whitelist file transfer
- **Mobile companion app** — thin Flutter client for Android/iOS connecting to Memo backend over LAN/ngrok
- **Remote access** — built-in ngrok tunnel support for accessing your backend anywhere
- **Backup/Restore (.memo)** — zip-based full data export/import with wipe capability
- **Windows support** — 8 compatibility fixes, Inno Setup installer
- **Memory bug fixes** — file sizes now display correctly, hardcoded Turkish strings replaced with L10n, fire-and-forget calls fixed with proper error handling

## 🔥 New Features

### Mobile Companion App (`mobile/`)
- **Fully separate Flutter project** targeting Android, iOS, Linux, macOS, Windows, and Web
- **ConnectScreen** — connect to Memo backend by LAN IP or remote URL with optional `X-Memo-Token` auth, local/remote toggle
- **ChatScreen** — streaming SSE support, message list with Markdown rendering, session drawer, typing indicator
- **SettingsScreen** — 3 tabs: General (backend URL, token), Providers (view/toggle/delete), Models (list, start/stop)
- `/model` command for runtime model switching
- Riverpod state management, Material 3 theming
- **All AI processing stays on the desktop** — mobile is a thin remote viewport
- *Future roadmap: RAG, WhatsApp, Orchestra, Agent, cloud sync, backup on mobile*

### Remote Access (ngrok)
- `internal/ngrok/` — `installer.go`, `manager.go`, `ngrok.go`
- Automatic ngrok binary download and tunnel management
- Configurable domain, region, and port forwarding
- Works alongside local setup — switch between local and remote access
- Refactored orchestra initialization to be ngrok-aware

### WhatsApp Integration
- WhatsApp Web QR pairing (`internal/whatsapp/`)
- Local isolated SQLite message store (separate from main database)
- Contact name resolution (`resolveDisplayName()`): phonebook sync, push names, fallback to phone number
- `importContacts()` — imports full phonebook from whatsmeow on startup
- Bidirectional messaging (`SendMessage()`, `handleMessage`, `handleHistorySync`)
- **Whitelist-based file transfer:** trusted contacts can request files from whitelisted directories; automatic authorization checking
- Agent toolset: `SendWhatsApp`, `SearchWhatsApp`, `LatestWhatsAppChats`, `GetWhatsAppMessages`
- Dedicated WhatsApp chat mode with isolated executor and tool registry
- `waToolAdapter` adapting `tools.WhatsAppClient` interface
- Endpoints: `POST /api/whatsapp/chat-stream`, `GET/POST /api/whatsapp/chat-mode`
- Frontend: QR display (`qr_flutter`), chat toggle, dedicated WhatsApp screen
- `importContacts` nil pointer fix: `Store.Contacts` nil check added

### Backup / Restore (.memo)
- `GET /api/export` — export all data as zip
- `POST /api/import` — restore from zip
- Scope: `sessions/`, `config/config.yaml`, `providers.json`, `orchestra.json`, `memory/`, `whatsapp/`
- Models optional (`?include_models=true`)
- **Wipe All Data:** `POST /api/wipe` — double-confirm to delete everything
- Frontend: `_BackupRestoreTab` (Export/Import/Wipe buttons, "Include models" toggle)
- **Export bug fix:** `filepath.Rel(src, path)` fixed (double nested zip error)
- **Import bug fix:** hardcoded `data/` prefix removed, correct path mapping

### SQLite + sqlite-vec Vector Store
- `internal/database/sqlite.go` — WAL mode, write-queue, pool management
- `internal/database/vec_register.go` — custom driver + vec0 extension loader
- `internal/memory/store.go` — `SaveInteraction`, `RetrieveContext` (vec0 ANN + Go fallback)
- `internal/memory/embedder.go` — chromem-go dependency fully removed
- ANN search: `CREATE VIRTUAL TABLE vec_memories USING vec0(embedding FLOAT[...])`
- vec0 unavailable → Go brute-force cosine similarity fallback
- Memory store initializes in a goroutine (non-blocking server start)

### Cross-Mode (API + Local Embedding)
- `memory.embedding_model_repo` and `memory.embedding_model_file` config fields
- Auto-download + start embedding model on startup
- External provider chat while local model handles embedding
- Embedding server (`:8082`) unaffected by provider switches
- `embedding_auto_start: false` by default

### Windows Support (8 Compatibility Fixes)
- **Command execution** (`internal/agent/tools/command.go`): Linux uses `bash -c`, Windows uses `cmd /C`
- **Signal handling** (`main.go`): `syscall.SIGTERM` Linux/macOS only
- **Protected directories** (`internal/agent/sandbox.go`): Windows path protection
- **Recording stop** (`app.go`): `Process.Kill()` fallback
- **Machine key** (`internal/provider/config.go`): Windows `MachineGuid` registry
- **GPU detection** (`internal/llama/gpu.go`): Windows nvidia-smi path
- **Symlink** (`internal/llama/installer.go`): copy fallback on Windows
- **Cross-volume rename** (`app.go`, `internal/modelstore`): copy+delete fallback

### Windows vec0.dll
- sqlite-vec v0.1.9 Windows DLL (283 KB) under `binaries/windows/`
- Falls back to Go mode if vec0.dll is missing

### About & License
- "About" tab updated: AGPL v3 license, technology stack, refined vision text
- GitHub URL: `github.com/BugraAkdemir/memo`
- Google Drive backup UI removed, replaced by Backup tab

### Memory Settings Fixes
- **`ListGobFiles` SizeKB**: now computed from actual content length (`LENGTH(user_msg) + LENGTH(assist_msg)` in SQL) instead of hardcoded zero
- **Hardcoded Turkish strings replaced**: Memory toggle section and Clear Memory dialog now use `L10n.t()` keys for proper localization
- **Fire-and-forget bug fixes**: `toggle()`, `clearAll()`, `deleteFile()` calls are now properly awaited with try/catch and error snackbar feedback

### Setup Wizard Refactoring
- Complete rewrite of `SetupWizardView` in Flutter: step-by-step assistant persona selection, theme and language configuration
- 6 preset prompts (Normal, Fun, Formal, Technical, Creative, Buddy) in Turkish and English
- Custom prompt editor with preview
- Name-aware prompt generation

### Voice / STT
- `stt_proc_unix.go` + `stt_proc_windows.go` — platform-specific speech-to-text process management
- Audio recording endpoint with OS-level recording control

### Other Improvements
- `Setpgid` over `Pdeathsig` (Linux process cleanup)
- `LoadExtension .so.so` double-extension bug fix
- `sqrtf` symbol fix (patchelf with libm.so.6)
- Embedding port safety (`StartEmbeddingModel` port check)
- WhatsApp `Start()` idempotent + mutex
- `_foreign_keys=on` DSN (whatsmeow sqlstore)
- Orchestra conductor initialization refactored for dependency injection
- README.md and READmeTR.md rewritten in professional format
- Docs reorganized (ROADMAP 3→2, KNOWN_ISSUES consolidated)

## 📝 Notes

- **Migration**: Old `.gob` memories start fresh (migration script optional)
- **CGO required**: `CGO_ENABLED=1 go build/test/run` (MinGW GCC on Windows)
- **vec0.so/vec0.dll**: Auto-loaded; falls back to Go brute-force if missing
- **Embedding model default**: `nomic-ai/nomic-embed-text-v1.5-GGUF` (768 dim)
- **WhatsApp**: whatsmeow multi-device API, session stored under `data/whatsapp/`
- **WhatsApp messages**: Isolated SQLite database, independent from main memory
- **Mobile**: Thin client only; all AI/ML processing stays on the desktop backend
- **Backup format**: `.memo` = ZIP (open standard, can be inspected manually)
- **License**: GNU AGPL v3 (not MIT)
