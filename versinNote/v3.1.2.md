# Memo v3.1.2 — Release Notes

> **Open Beta** · July 5, 2026 · [Download](https://memo.bugradev.com)
>
> A follow-up to v3.1.1 focused entirely on one thing: **Memo now has a terminal CLI**, built from scratch as a Claude Code–style chat experience.

---

## Big Feature: The Memo CLI

Running `memo` from an interactive terminal no longer just starts the headless backend — it drops you straight into a full chat REPL, styled after Claude Code's own terminal UX.

### Live Composer & Command Menu
- A raw-mode line editor with cursor editing and Up/Down input history.
- Type `/` and a command dropdown opens immediately — no Enter required — navigable with the arrow keys, the same way Claude Code's composer works.
- A bare `/` opens a full arrow-key command menu as a fallback/alternative.
- Esc or Ctrl+C cancels an in-flight streamed reply instantly, without killing the whole session.

### Look & Feel
- A two-tone ASCII "MEMO CLI" block-letter banner on startup.
- A bordered welcome panel showing the active model/provider and whether memory (RAG/embedding) is on.
- Streamed replies reveal with a typewriter effect; a thinking spinner shows while waiting on the first chunk.
- Background-tinted, readable user input echo — fixed after an early version was unreadable on some terminal color themes.

### Slash Commands
- `/help`, `/models`, `/model [name]`, `/embedding [name]` — list and start local models or embedding models, with an arrow-key picker when no name is given.
- `/model-download [query]` — search Hugging Face for GGUF models and download one, with a live in-place progress bar.
- `/connect <base_url> <api_key> <model>` — attach an external OpenAI-compatible provider.
- `/gui` — launch the desktop app alongside the CLI, talking to the same running backend.
- `/clear` — start a brand-new, empty chat (the old one stays recoverable, it just stops being active).
- `/session [name|number|new|list]` — list, switch between, or create chats scoped to the current project directory; bare `/session` opens an arrow-key picker.
- `/exit` or Ctrl+D to quit.

### Conversation History Actually Persists
Previously every `memo` run started a brand-new, empty chat — closing the terminal meant losing the conversation. The CLI now looks for the most recently used chat rooted at the current project directory and resumes it automatically, replaying its history into the terminal, so picking `memo` back up continues right where you left off. `/clear` and `/session` give explicit control over when to reset or switch.

### Agent Mode In the Terminal
Tool-use (agent) permission prompts now surface directly in the CLI — see exactly what a tool wants to do and answer allow/deny inline, mid-stream, without leaving the terminal.

### Install, Update & Remove
- Reinstall or fully uninstall the CLI from **Settings → General** in the desktop app, backed by new dedicated backend endpoints.
- Fixed a stale `~/.local/bin/memo` symlink corrupting the real binary on relaunch.
- `memo` (and the Windows/macOS/Linux launcher scripts) now correctly attach to an already-running backend instead of failing to bind the port when a second instance starts.

### Reliability Fixes Found Building the CLI
- The CLI couldn't find the bundled `llama-server` binary or the `vec0`/sqlite-vec module — both searches only looked next to the executable, not one level up, where the installed CLI (`~/.memo/bin/memo`) actually sits relative to the bundle. Fixed for both.
- `llama-server`'s own verbose stdout/stderr no longer leaks into the interactive terminal, interleaving with the chat UI — it's redirected to its own log file unconditionally.
- Fixed a spinner goroutine leak on a zero-chunk reply (an upstream hiccup with no SSE output at all), which used to garble the next prompt's output.
- The embedding model's auto-start could die moments after launching from a rare, transient process race — it now retries up to 3 times instead of silently leaving memory off until the user manually restarted it.
- Backend shutdown is now bounded to 15 seconds with independent subsystems stopped in parallel, instead of one slow component blocking the whole exit.
