# Memo v3.3.3 — Release Notes

> **Open Beta** · July 10, 2026 · [Download](https://memo.bugradev.com)
>
> A stability and trust-focused release: the terminal CLI stops getting stuck, the CLI and desktop app can now run side by side without stepping on each other, and Memo finally has a real, grounded answer when you ask who made it.

---

## Big Fix: The CLI No Longer Gets Stuck

A batch of reliability fixes for the terminal CLI introduced in v3.1.2 — the kind of thing that only shows up once people actually live in the terminal day to day.

- **`/model-download` no longer hangs.** Its progress bar used to read only from a timer, never from the keyboard — once a download started, there was no way to cancel it, and a slow connection could leave the whole terminal frozen until it finished or failed. Downloading models now happens in the desktop app instead, where there's a real, cancellable progress bar; `/model-download` in the CLI just opens the GUI for you.
- **`/gui` actually finds the desktop app now.** It was looking in the wrong folder on a real install and would always report "GUI not found" even when it was right there.
- **`/model` and `/embedding` no longer fail on slower hardware.** Loading a larger model could legitimately take over a minute — the CLI used to give up after 10 seconds and report a failure even though the model went on to load successfully in the background. It now waits as long as the backend actually needs, and Esc/Ctrl+C lets you stop waiting without losing the load in progress.
- **Pasting multi-line text works properly.** A pasted paragraph or code block used to get split into several separate messages line by line (and any line starting with `/` would run as a command). A full paste now lands as a single message, sent only when you actually press Enter.
- **The terminal no longer gets left in a broken state.** If the CLI was closed by something other than `/exit` (a script, a process manager), the terminal used to stay unresponsive until you ran `stty sane`. It's restored properly now.

## Big Feature: CLI and Desktop App Run Independently

Previously, if the terminal CLI started its own backend and you then opened the desktop app with `/gui`, closing the CLI would silently take the backend — and the still-open desktop app — down with it.

- The CLI's backend now runs as its own separate process, not bundled inside the terminal session.
- The backend stays alive as long as *either* the CLI or the desktop app is actually using it — closing one no longer disrupts the other.
- Once neither is open anymore, the backend shuts itself down on its own within about a minute or two, instead of lingering in the background using memory for nothing.

## New: Memo Knows Who Made It

Ask Memo who built it, what it's for, or what it stands for, and it now gives a real answer instead of guessing: built solo by Buğra Akdemir — a 16-year-old developer — with no commercial motive, released open source for people who care about their privacy. Local-first, works offline, remembers you without sending your data anywhere.

This only ever comes up if you actually ask — it doesn't change how Memo talks day to day, and it's included no matter which personality you picked during setup.

## New: Minimal Mode (Settings → General)

A toggle for people who want their local model running with as little overhead as possible. When it's on, Memo skips all personality, mood, and web-search instructions entirely — only memory (if you've also got that turned on) still reaches the model. With both switched off, nothing extra goes in at all: just your message, exactly as typed.

## Small Fix: Engine Status Bar

The status bar under the chat box could show its "no model running" and "no memory model" messages squished together with no gap between them when the app was fully offline. Spaced out properly now.
