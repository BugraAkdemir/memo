# Memo v3.3.3 — Release Notes

> **Open Beta** · July 10, 2026 · [Download](https://memo.bugradev.com)
>
> A stability and trust-focused release: the terminal CLI stops getting stuck, the CLI and desktop app can now run side by side without stepping on each other, and Memo finally has a real, grounded answer when you ask who made it.

---

## Big Fix: The CLI No Longer Gets Stuck

A batch of reliability fixes for the terminal CLI introduced in v3.1.2 — the kind of thing that only shows up once people actually live in the terminal day to day.

- **`/model-download` no longer hangs.** Its progress bar used to read only from a timer, never from the keyboard — once a download started, there was no way to cancel it, and a slow connection could leave the whole terminal frozen until it finished or failed. Downloading models now happens in the desktop app instead, where there's a real, cancellable progress bar; `/model-download` in the CLI just opens the GUI for you.
- **`/gui` actually finds the desktop app now.** It was looking in the wrong folder on a real install and would always report "GUI not found" even when it was right there.
- **`/model` and `/embedding` no longer fail on slower hardware.** Loading a larger model could legitimately take over a minute — the CLI used to give up after 10 seconds and report a failure even though the model went on to load successfully in the background. It now waits as long as the backend actually needs, and Esc/Ctrl+C lets you stop waiting without losing the load in progress.
- **Pasting multi-line text works properly.** A pasted paragraph or code block used to get split into several separate messages line by line (and any line starting with `/` would run as a command). A full paste now lands as a single message, sent only when you actually press Enter.
- **The terminal no longer gets left in a broken state.** If the CLI was closed by something other than `/exit` (a script, a process manager), the terminal used to stay unresponsive until you ran `stty sane`. It's restored properly now.

## Big Feature: CLI and Desktop App Run Independently

Previously, if the terminal CLI started its own backend and you then opened the desktop app with `/gui`, closing the CLI would silently take the backend — and the still-open desktop app — down with it.

- The CLI's backend now runs as its own separate process, not bundled inside the terminal session.
- The backend stays alive as long as *either* the CLI or the desktop app is actually using it — closing one no longer disrupts the other.
- Once neither is open anymore, the backend shuts itself down on its own within about a minute or two, instead of lingering in the background using memory for nothing.

## Fixed: Embedding Model Could Get Stuck Until Reboot

If the embedding model failed to start even once — usually because a leftover process from an earlier crash was still holding its port — it stayed broken until you rebooted your whole computer. Every retry failed the exact same way because the real cause was never actually touched. Memo now clears a stuck port automatically before every attempt to start the embedding (or chat) model, so a one-off failure no longer needs a reboot to recover from.

## Changed: The Terminal CLI Always Starts a Fresh Chat

Opening the CLI used to automatically resume your last conversation, carrying over old context whether you wanted it or not. It now always starts clean — use `/session` to jump back into any earlier conversation whenever you actually want to.

`/session` also now shows every chat, not just ones started from the CLI in the current folder — chats started in the desktop app show up too, and you can pick up any of them from the terminal, in either direction.

## New: Memo Knows Who Made It

Ask Memo who built it, what it's for, or what it stands for, and it now gives a real answer instead of guessing: built solo by Buğra Akdemir — a 16-year-old developer — with no commercial motive, released open source for people who care about their privacy. Local-first, works offline, remembers you without sending your data anywhere.

This only ever comes up if you actually ask — it doesn't change how Memo talks day to day, and it's included no matter which personality you picked during setup.

## New: Minimal Mode (Settings → General)

A toggle for people who want their local model running with as little overhead as possible. When it's on, Memo skips all personality, mood, and web-search instructions entirely — only memory (if you've also got that turned on) still reaches the model. With both switched off, nothing extra goes in at all: just your message, exactly as typed.

## New: Two More Providers — OpenCode Zen & OpenCode Go

Added OpenCode's two gateways as API providers. Like OpenRouter, you don't type a model name by hand — hit "Seç" (Choose) in the provider dialog and pick from the real, live list of models the API actually offers.

- **OpenCode Zen** — pay-as-you-go, some models free.
- **OpenCode Go** — subscription-based.

## Big Feature: Import Your Memory From Another AI

Settings → **Hafızayı İçe Aktar** (Import Memory) is a new page that lets Memo learn everything another AI assistant (ChatGPT, Gemini, Claude, whatever you already use) knows about you, in one step.

- Copy the provided prompt into your other AI's chat — it asks that AI to describe you back in a structured way (demographics, interests, relationships, upcoming events/plans, communication style, standing instructions).
- Paste its answer back into Memo and hit **Hafızaya İşle** (Save to Memory).
- Memo sends that text to your active model, which breaks it into individual, atomic facts and saves each one the same way `/remember` does — plus a separate "how you like to be talked to" summary that gets folded permanently into Memo's own system prompt, not just probabilistically recalled like a fact.
- A tip banner reminds you to actually chat with the other AI for a while first — an assistant with little history to draw on will only give Memo a thin, mostly-empty result back.

Works with whatever's currently active — local model or an external API provider — and fails fast with a clear message if nothing is connected, instead of hanging.

## New: Skill Tools Can Actually Run Now

A skill's `SKILL.md` could always *declare* tools in its front matter, but until now that was purely decorative — there was no way for one to actually execute anything. Skill tools are now real: a skill can define a `command:` field, and Memo wires it into the exact same agent tool pipeline (and the exact same permission-prompt UI) that `run_command`/file-edit tools already go through — so a skill's tools get the same "ask before running" safety net as everything else, with zero extra setup.

## Fixed: `/remember` Wasn't Actually Saving Anything

A one-character bug in the database insert meant every single call to explicit memory saving — the `/remember` chat command, and the new memory-import feature above — silently failed every time, with no error shown anywhere. It's been there long enough that this may be the first release where `/remember` actually works.

## Fixed: Memory Could Silently Stay Off After a Restart

If an embedding server was already running (left over from an earlier session, or started manually) when Memo's backend started up, memory/RAG used to keep talking to a placeholder connection instead of the real thing — while the status indicator confidently reported "running" the whole time. Memo now checks for an already-running embedding server on startup and reconnects to it properly.

## Big Fix: Memory Actually Remembers What You Tell It

A cluster of related fixes to how Memo recalls saved information, all found and fixed in one focused pass:

- **Keyword-based memory search was never actually active in any release.** Memory has always been designed to combine two ways of searching — one based on meaning, one based on exact words — but the exact-word half silently failed to start up in every single build ever shipped, with no visible error anywhere. Fixed; both halves now genuinely work together.
- **Questions covering several topics at once could come back incomplete**, even when everything asked about had been saved — asking about your name, birthday, and favorite color together could return two out of three, seemingly at random. Each topic in a multi-part question is now searched for on its own instead of being blended into one.
- **New: personal facts you mention in ordinary conversation are now recognized and remembered reliably** — not just things saved through the explicit `/remember` command. Mention your dog's name, your birthday, your job, in a normal sentence, and Memo quietly keeps track of it from then on, without it having to compete with everyday small talk for a spot in what it recalls.

## Security Fixes

- **Remote access now requires the access token.** If you've turned on remote access (LAN or ngrok) to reach Memo from your phone or another device, every request now has to present the access token shown in Settings. Previously, anyone who could reach that address at all — same Wi-Fi, or your ngrok link — could read your provider API keys, wipe your data, or run commands on your machine, with zero credentials. The mobile app already sent this token, so nothing changes for it; a custom tool built directly against the remote API now needs it too. Local-only use (the default, with remote access off) is completely unaffected.
- **Hardened the agent's dangerous-command filter.** A gap in the pattern matching meant a handful of specific destructive commands (like wiping a root or home directory) could slip past the safety check meant to catch them before the agent ever runs anything. Every agent action still needs your explicit approval regardless — this closes a gap in the extra safety net underneath that.

## New: Agent Mode Toggle in the Chat Bar

Turning agent mode (file/command tools) on used to mean leaving the plain Chat screen for the separate Agent tab — there was no way to reach it from an ordinary chat. A toggle now sits right in Chat's top bar, next to the existing web-search toggle.

## New: Report a Bug (Settings)

A new "Hata Bildir" / "Report Bug" tab in Settings. Describe what happened, optionally check a box to attach your last 10 background error events, and hitting the button opens a prefilled GitHub issue in your browser — nothing is sent anywhere until you review it on GitHub's own page and submit it yourself, with your own account. No screenshots, no background upload, no new server on our end collecting anything: the report goes to GitHub, sent by you, not to us. That's a deliberate choice to keep "we collect zero data" simple and true.

## Fixed: Agent Mode Could Fail With Certain Providers

Turning on agent mode (file/command tools) and sending a message could fail outright against some external providers with a cryptic `400 invalid_request_error`, while the exact same provider worked fine for plain chat. An internal bookkeeping field was accidentally leaking into the tool definitions sent to the provider's API — harmless noise to providers that ignore unrecognized fields, but rejected outright by stricter ones. That field never did anything useful and has been removed.

While in there, error messages shown in chat are also cleaner now: instead of dumping a provider's entire raw JSON error response, Memo pulls out just the actual human-readable message.

## New: Usage Stats (Settings → Stats)

A new tab: total requests, total input/output tokens, average tokens/second, and most-used model as KPI cards up top; a stacked bar chart of the last 30 days' daily token usage and a per-model breakdown below. The backend records every completed turn (local model, agent, orchestra, or external provider — doesn't matter which) to its own dedicated database, except in incognito mode. Cost ($) is deliberately not shown — no provider exposes real pricing data backend-side today, and shipping a static, unmaintained price table felt worse than leaving it out.

## Big Fix: `.memo` Backup Is Now Actually Complete

The backup feature never included calendar events, learned habits, routines, task lists, agent tool permissions, or installed skills — only chats, memory, provider config, and WhatsApp data made it in. Worse: `machine.key`, which decrypts `providers.json`'s encrypted API keys, was **never exported at all** — restoring that backup on a different machine, or after a data wipe, silently and permanently left every API key undecryptable. Everything is now included (models excluded, but already optional via their own toggle). Still deliberately excluded: the device-specific Drive sync cursor, the machine-specific tsnet identity, and the backup function's own snapshot directory.

## Big Feature: Developer API Gateway (Sidebar → Developer)

A new local API that makes Memo usable from tools that only support an Anthropic-compatible endpoint — most notably **Claude Code**, via `ANTHROPIC_BASE_URL`. Point Claude Code at Memo and it runs your own local model or your own OpenAI/Gemini/etc. API key behind the scenes — model selection uses a `type/model-id` format (`local/qwen2.5`, `openai/gpt-4o`, and so on).

- **Full agentic tool calling works** — reading/writing files, running commands, the actual power behind Claude Code, is fully supported (for the openai/custom/local/groq/openrouter/grok/opencode-zen/opencode-go providers; not yet for gemini/claude/ollama, whose own provider implementations don't support tools at all — a tools-bearing request to one of those gets a clear error instead of silently dropping the tools).
- API key requirement is optional (off by default, shares Remote Access's token), memory integration is optional (off by default, and even when on, never creates a visible chat session).
- Has its own screen in the sidebar (like WhatsApp/Calendar/Routines), not tucked inside Settings — Base URL, model list, and token are all copy-paste ready, alongside a live log showing every request passing through the gateway as it happens.

## Small Fixes

- **Memo now explains *why* a feature is off instead of denying it exists.** Asking it to search the web or edit a file when those toggles were off used to get "I don't have that ability at all" — even though both features exist, just weren't enabled for that chat. It now knows the difference and says so.
- **Memo now knows about its own always-on calendar/reminder detection.** Asked directly "can you set a reminder for me," it used to flatly deny having any such system — even while it was quietly creating one in the background for that very message. It now says yes.
- **Several Settings screens didn't fully respect the Turkish/English language switch.** A number of labels, buttons, and messages across Settings stayed in one language regardless of the toggle. Now consistent everywhere.
- **The terminal CLI tells you the real reason if memory saving fails**, instead of a misleading "hafıza: açık" banner or silence where a save confirmation should be.
- **Remote-access token now survives an app restart.** If you'd turned on LAN/ngrok access, the desktop app previously forgot the token on every relaunch and needed it re-entered before the first request worked again.
- **Shift+Tab auto-permission mode actually works now.** A timing issue meant the toggle could look like it took effect in the UI while the agent kept prompting for permission on every tool call anyway.
- **The tool-permission dialog no longer disappears if it fails to reach the backend.** It used to close either way, leaving the agent stuck waiting for a decision it never got. It now stays open and shows what went wrong so you can retry.
- **The tool-permission dialog also no longer lingers if you stop the response or switch chats while it's open.** It now closes itself automatically instead of staying on screen for a request that no longer exists.
- **Switching chats right as a response is being generated no longer risks it landing in the wrong chat.** A rare timing window meant a reply could occasionally get attached to whichever chat became active in the meantime instead of the one it was actually replying to.
- **A clearer message if you switch models or providers exactly while a response is streaming.** Instead of a confusing connection error, you now get a plain explanation of what happened.
- **Fast double-clicking the Memory or Minimal Mode switch no longer lands on the wrong setting.**
- Engine status bar: the "no model running" and "no memory model" messages could show squished together with no gap between them when the app was fully offline. Spaced out properly now.
