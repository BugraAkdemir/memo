# Memo v3.3.4 — Release Notes

> **In Development** · Not yet released
>
> A stability-focused follow-up to v3.3.3: expanding test coverage into the parts of the codebase that have none yet, closing the remaining half of the pinned-facts/local-model contention issue, running a fresh deep bug-scan pass over modules that haven't had one, and fixing a Windows install issue (missing `msvcp140.dll` on machines without the Visual C++ Runtime already installed).
>
> This file is a running draft, filled in as work lands — not a final changelog yet.

---

## Planned

- **Test coverage** for previously untested areas: `handlers_oauth.go`, `handlers_proactive.go`, `internal/cloudsync/drive.go`, `hardwareID()`.
- **Local model contention** — the remaining half of the pinned-facts/auto-fact-extraction TD-2 item: chat, pinned-facts consolidation, and auto-fact-extraction currently compete for the same single local inference slot.
- **Deep bug-scan pass** over modules not yet covered by the multi-agent review done for v3.3.3 (`internal/cloudsync`, `internal/skill`, `internal/proactive`, `internal/observer`).
- **Fixed: Windows installs could fail to launch with a missing `msvcp140.dll` error.** A clean Windows machine without the Visual C++ Runtime already installed (common on fresh VMs and some new PCs) couldn't start Memo at all. The installer now bundles the Visual C++ Redistributable and installs it silently, with no extra step needed from the user.
