# Memo v3.3.4 — Release Notes

> **In Development** · Not yet released
>
> A big reliability and polish release: every background task in the backend now survives an unexpected error instead of silently taking the whole app down, turning on memory could quietly cut local generation speed by 4-5x and is now fixed, a new (beta) **Live Mode** lets you have a hands-free spoken conversation with Memo, **Tailscale remote access graduates out of Beta** with one-click login, the terminal CLI gets a Shift+Tab auto-approve toggle matching the desktop app plus a new default look you can switch away from with `/theme`, Settings is reorganized into a searchable rail instead of 20 flat tabs, and a batch of real bugs got fixed — agent mode failing on short messages with small local models, "Delete All Data" not working on Windows, speech-to-text not starting from an installed CLI, web search firing on every single message instead of only when actually needed, and more. The setup wizard and model store also got a pass of plain-language error messages and tooltips for non-technical users.
>
> This file is a running draft, filled in as work lands — not a final changelog yet.

## Big Fix: The Backend No Longer Crashes From a Background Error

An unexpected error in almost any background task — memory saving, a routine tick, a WhatsApp message handler, a proactive-suggestion check, a streaming reply — used to be able to crash the *entire* Memo process, not just that one task, because Go gives no automatic protection for code running in the background the way it does for a single request. Before this release, only three small corners of the codebase had any protection against that at all.

Every background task across the whole backend (memory, chat streaming, WhatsApp, cloud sync, local model management, speech-to-text, routines, proactive suggestions, notifications, remote-access tunnels, and more) is now guarded: if something unexpected goes wrong in one of them, it's logged and contained instead of taking Memo down with it. This is a foundational stability fix — it doesn't change how any feature behaves when everything's working normally.

## Big Fix: Turning On Memory Could Cut Local Generation Speed by 4-5x

Reported directly: enabling memory/RAG on a local model could tank generation from roughly 10 tokens/sec down to 2-3, with memory switched off running faster than that. Two compounding causes, both fixed:

- The dedicated embedding server was auto-starting with GPU auto-detect — sized as if it were the only model running — even while the chat model's own server was already resident and already using most of the GPU's VRAM. The two servers oversubscribed VRAM together, pushing the chat model into partial CPU fallback for the rest of the session. The embedding server now defaults to CPU-only (small enough to stay fast there anyway), fully removing the contention instead of just easing it; a new `embedding_gpu_layers` config option lets you opt it back onto the GPU if you have real headroom to spare.
- Separately, the memory block injected into every prompt (retrieved results plus facts pinned via `/remember`, which only grow over a session and are never trimmed) had an old 16K-token budget that was never a real ceiling for how this app actually uses it. It's now capped at a much closer 4096 tokens, bounding worst-case prompt bloat as the pinned-facts set keeps growing over time.

## New (Beta): Live Mode — Hands-Free Voice Conversations

A small voice icon next to the chat input box (after turning on **Settings → Beta Features**) lets you talk to Memo out loud instead of typing: it listens for your voice, automatically detects when you start and stop speaking, transcribes it, sends it as a normal chat message, and speaks the reply back to you — a real spoken back-and-forth, hands-free, right inside any chat rather than a separate screen.

- Speech is transcribed locally (the same on-device transcription Memo already uses elsewhere). Replies are spoken with **Piper**, a local, offline text-to-speech engine, by default — nothing about a Live Mode conversation has to leave your machine. Settings → Beta Features also lets you configure an external TTS provider (OpenAI) instead, if you'd rather trade the local-only guarantee for a different voice; local Piper is still the fallback whenever none is configured or a call fails.
- **Pick and download an offline voice.** Settings → Beta Features' local voice picker downloads a small, curated set of Piper voices (Turkish and English) and switches to one instantly — no restart needed.
- **One-directional barge-in.** Speak again while Memo is thinking or replying and it stops what it was doing and listens to your new message instead of talking over you.
- A short, locally-synthesized "thinking" sound (hmm/mm/ah) now plays during the gap while Memo generates a reply, so the pause doesn't feel like it's frozen.
- The voice-activity model that detects when you start/stop speaking now ships bundled with the app instead of downloading from a CDN at runtime — fixes an early source of instability some testers hit.
- Works on Linux, Windows, and macOS.
- **Known limitation**: there's no echo cancellation yet, so using speakers instead of headphones can occasionally make Memo mistake its own voice for you interrupting it. Full duplex audio is planned for a later release.

## New (Beta): Claude Code and Codex CLI as Chat Providers

Settings → API Providers → Add Provider now includes **Claude Code (CLI)** and **Codex (CLI)** — instead of calling an API, Memo shells out to your locally installed `claude` or `codex` command-line tool. Pick either from a chat's own model picker and that chat becomes a thin front-end for a real coding agent, not just another chat model: it can read/edit files and run commands in a folder you choose, using each CLI's own no-prompt permission mode (`--dangerously-skip-permissions` for Claude Code, `--dangerously-bypass-approvals-and-sandbox` for Codex, since there's no terminal for either to prompt in).

- **Per-chat, not app-wide.** Each chat remembers its own provider — picking a CLI provider in one chat never touches any other chat's model or provider, so you can run a coding agent in one tab and a normal conversation in another at the same time.
- **Runs as a real background job.** Switch to a different chat, or close the window, and the CLI keeps working — Memo tracks it independently of whatever you're looking at. Only an explicit cancel or fully quitting Memo stops it. The chat sidebar shows a small spinner on a chat while its CLI job is running, and a dot (cleared the moment you open it) once it finishes if you weren't watching.
- **No fixed timeout.** A long-running CLI task isn't cut off at the 5-minute budget every other reply has — it runs until it's done or you cancel it.
- **A one-time setup per chat.** The first time you pick a CLI provider for a chat, a short warning explains this is a real agent with file/shell access, then a folder picker sets where it should run — asked once, remembered after.
- **Settings → CLI Bağlantıları** (CLI Connections) checks whether `claude`/`codex` are actually installed and on your PATH, with their version if so.
- **Deliberately sends no memory or identity context.** The CLI receives only your raw message — it manages its own multi-turn session and already has its own project-context mechanisms, so Memo doesn't duplicate that.
- **The CLI's own slash commands work.** Type `/` in a CLI chat and you get that CLI's real commands — the ones you've written under `.claude/commands` / `.codex/prompts`, its skills, and the built-ins that do actual work — each labeled with where it came from (project, personal, skill, built-in), instead of Memo's own prompt templates. Claude Code runs them natively; Codex resolves custom prompts only in its own interactive terminal, so Memo expands those itself (arguments included) before handing the request over.

This is an early integration: there's no UI yet for reviewing what the CLI actually did (file edits, commands run) beyond its final text reply. A handful of rough edges found during live testing were also fixed along the way: the top model pill could show the app's stale global model instead of a chat's actual CLI provider, the one-time setup dialog could fail to appear the first time you picked a CLI provider (only showing up the second time), the `/` and `@` popups in a CLI chat didn't respond to arrow keys, the mouse wheel, or clicks at all, and a CLI chat could lose your own message on reload and never generate a title.

## Changed: Remote Access (Tailscale) Graduates Out of Beta

Tailscale-based remote access — reaching Memo securely from your phone or another device without exposing it to the open internet — no longer needs the Beta Features switch; Settings → Remote Access has it directly, on desktop and mobile alike.

- **One-click login.** Connecting used to require pasting a Tailscale auth key by hand; it's now an interactive login flow, no key needed.
- **Funnel defaults to on**, since without it a phone can only reach the tunnel over the same tailnet — turning it off now shows a warning explaining what you'd lose first.
- **Auto-reconnects after a dropped connection** instead of silently staying dead until you noticed and restarted the app — covers both a killed listener and a silent tailnet drop that used to leave the status indicator lying about still being connected.
- Retries connecting at boot instead of giving up after one failed attempt, and no longer blocks app startup for minutes if a background reconnect hangs.
- The mobile app also auto-reconnects with the saved URL on a cold start, and shows a real error message instead of a raw exception dump when a connection drops.

## New: @ File-Mention in Chat

Type `@` in any chat's message box and a dropdown lets you search for and reference a file by name — useful for pointing agent mode at a specific file without typing out its full path.

## Changed: Settings Reorganized Into a Searchable Rail

Settings used to be a flat row of about 20 tabs. It's now a grouped, searchable rail on the left with a search box up top — type a few letters of what you're looking for and jump straight to it instead of scanning every tab by eye.

## Fixed: A New Chat Message Could Queue Behind Background Memory Work

On a local model (which processes one request at a time), sending a message right after Memo finished quietly extracting a fact from your previous turn could leave that new message waiting in line behind it instead of starting right away — a small but real delay that only affected local-model setups. A real chat message now cancels any in-flight background memory call before it's sent, so background bookkeeping never holds up an actual conversation.

## Fixed: Agent Mode Could Fail on a Single-Word Message With a Small-Context Local Model

Sending even a one-word message ("selam"/"hi") with agent mode on could fail outright on a local model with a small context window, with a confusing "request exceeds the available context size" error. Agent mode's tool definitions (12+ tools, sent to the model on every request) were never counted against the context budget at all — Memo thought the request fit when the real request, tools included, didn't. Fixed at the source: agent mode's tool schema is now correctly budgeted against your model's context size. The default local context size was also raised (4096 → 8192) for more headroom, and starting a model that doesn't actually support tool calling now shows a clear warning instead of failing unexplained later.

## Fixed: "Delete All Data" Could Fail on Windows

Settings → Backup's "Delete All Data" (factory reset) worked on Linux but could fail outright on Windows. The cause: several of Memo's internal databases (memory, usage stats, calendar, mood, WhatsApp) were still open when the wipe tried to delete their files — harmless on Linux, but Windows refuses to delete a file that's still in use by the same process. Every store is now properly closed before its files are removed.

## Fixed: Speech-to-Text Couldn't Find Its Bundled Files From an Installed CLI

Starting speech-to-text from an installed terminal CLI (as opposed to the desktop app) could fail with "whisper-server binary not found," because it was only looking for the bundled binary right next to the CLI's own executable — not in the separate folder one level up where an installed CLI's bundled files actually live. Fixed; unaffected if you only ever use the desktop app.

## Fixed: Windows Installs Could Fail to Launch With a Missing `msvcp140.dll` Error

A clean Windows machine without the Visual C++ Runtime already installed (common on fresh VMs and some new PCs) couldn't start Memo at all. The installer now bundles the Visual C++ Redistributable and installs it silently, with no extra step needed from the user.

## New: Plain-Language Errors, Tooltips, and Download Time Estimates

Memo's setup wizard and model store are meant to work for non-technical users, but still surfaced some raw, developer-facing failure messages. A pass of small fixes aimed squarely at that:

- Model start/download failures now show a short, actionable message ("couldn't reach the server," "not enough memory to load this model," etc.) instead of a raw error string like `llama: server failed to become ready within 120s`.
- The GGUF/quantization badge and the hardware-fit badge (Fits / CPU OK / Too Large) now have hover tooltips explaining what they actually mean, without hiding the technical labels for users who already know.
- Download progress now shows a rough time estimate, not just a bare percentage — and the wizard is upfront that fully closing the app restarts a download from scratch (Memo doesn't support resuming a partial download yet), instead of leaving that unstated.

## New: Quick Model Switcher, a Friendlier "No Model" Guide, and a Setup-Wizard Provider Shortcut

- Chat's top bar now shows the active model/provider as a pill you can click to switch, without leaving the chat screen or digging into Settings.
- Sending a message with no working model or provider connected used to surface a raw backend error. It now shows a short explanation of what's missing and a button that opens the model switcher directly, without losing what you'd already typed.
- The setup wizard's model step now offers connecting an external API provider as an alternative to downloading a local model — and warns if you go that route without a local memory model, since chat will work but Memo won't remember anything between messages without one.

## New: Shift+Tab Auto-Approve Now Works in the Terminal CLI Too

The desktop app has had a Shift+Tab shortcut to auto-approve every agent tool call (skip the "allow this?" prompt entirely) for a while — the terminal CLI didn't. Same shortcut, same toggle, now in both places: press Shift+Tab in the CLI to stop being asked before every file edit or command during a multi-step agent task, with a status line showing when it's on.

## New: A New Default Look for the Terminal CLI, With `/theme` to Switch

The terminal CLI's look was modeled closely on Claude Code's own — testers said as much directly, and wanted something that felt like Memo's own. It now defaults to a new, simpler look: no boxed welcome panel, just one line (model, project, memory status), and the bottom status bar shows live data (model, memory, whether auto-approve is on) instead of a static list of keyboard hints.

- Type `/theme` to switch — on a real terminal this opens an arrow-key picker (same as `/model` or `/session`), no need to type a theme's name.
- The original boxed look is still there if you preferred it — pick "claude-code" from the same picker.
- Your choice is remembered for next time; it's a purely local terminal preference, not something that touches your account or the desktop app.

## Fixed: A Multi-Step Agent Task Used to Fill the Terminal With One Line Per Tool Call

Asking the CLI's agent mode to do something that took several steps (read a folder, write a file, run a command) used to print a permanent line for every single step — `⚙ write_file çalışıyor...`, `✓ write_file tamamlandı`, and so on for each one, turning an ordinary request into a wall of scrollback. Tool activity is now shown as a single status line that updates in place instead, the same idea as the "thinking" spinner it already had — nothing extra is left behind once the reply arrives.

While fixing this, a real (not just cosmetic) bug in that same status line was also found and fixed: a narrow timing window could freeze the terminal outright, with two status updates visibly garbled together on one line — reported directly, with a screenshot showing exactly this. Fixed at the source (a lock that was held longer than it should have been).

## Fixed: Confusing "Access Denied" Errors When the Agent Tried to Read or Write Outside Your Project

The terminal CLI's agent only ever reads/writes files inside the folder you started it in — a safety boundary, and it was already working correctly. The error it showed when something fell outside that boundary just never said what folder *was* actually allowed, so the model (and you, reading the same message) had nothing to correct toward, and it would often blindly retry with a different tool or path a few times before giving up or finding the right one. The error now names the actual project folder directly.

## Fixed: Web Search Ran on Every Single Message, Even "hi"

Turning web search on used to mean *every* message got a live web search injected into it behind the scenes, no matter what it actually was — greetings included — while, separately, agent mode already has its own web-search tool that the model is instructed to reach for only when a message genuinely needs current information. Both were running at once: the smart, selective one sitting unused while a second, dumber mechanism searched blindly every time. The blind version now only runs when agent mode is off (where it's still needed, since there's no other way to bring in search results at all); with agent mode on, the smarter tool-based version handles it alone, deciding per message the way it was always meant to. This fixes the same behavior in the desktop app too, since both share this code path.

## Small Fixes

- **The Linux launcher (`run_memo.sh`) could start the frontend from the wrong working directory.** Fixed.
- **A local model's first ("cold") start could look like it had hung.** It was silently taking over a minute with no explanation while it was actually still loading successfully in the background; it now explains what's happening while you wait.
- Provider save errors in the provider connection dialog now show inline instead of nowhere.

## Security Fixes

- **Dependency security fix.** A vulnerability flagged by `govulncheck` in `google.golang.org/grpc` (an indirect dependency pulled in via the Google Drive cloud-backup integration) was patched by updating the dependency.
