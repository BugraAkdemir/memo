## Self-hosting: the biggest thread so far

The single largest body of work heading into v3.5.0 is turning Memo from a
desktop-only app into something you can also run as a real, always-on
service — a Raspberry Pi, a home server, a VPS — managed entirely over SSH.
This is still pre-release, unpublished work (nothing below is on a tagged
version yet), but a substantial amount of it already exists and works
end-to-end on `main`:

- **Docker/CasaOS support** — a multi-arch (amd64 + arm64) image publishes
  automatically to GHCR on every push. Native arm64 installs and packaging
  (Raspberry Pi included) already existed before this cycle; this closes
  the Docker side of the same story. *Not yet live-verified on a real Pi.*
- **A real auth system for remote access** — four selectable modes
  (no-credential/token/password/token+password), argon2id password
  hashing, brute-force lockout on login, short-lived signed sessions, and
  per-device tokens (hashed at rest, shown once, revocable individually) —
  replacing the single shared token every remote-access request used to
  compare against.
- **`memo` CLI grew real self-hosted-management commands**: `memo config
  get/set` (edit config.yaml from a script), `memo remote` (auth mode +
  device management, the same REST endpoints Settings uses), `memo
  service install/uninstall/status` (a systemd `--user` service with
  auto-restart) — the whole "manage it over SSH" story the roadmap called
  for.
- **A dedicated server-only installer** (`get-memo-server.sh`) — same
  release archives as the desktop installer, but skips the Flutter
  desktop binary entirely; for a machine that has no display to show it
  on in the first place.
- **The minimal built-in web page** (already existed for CasaOS/headless
  use) gained a Remote Access status panel and an emergency restart
  button, for the rare moment nothing else is reachable.
- A real CORS bypass in the existing remote-access gate was found and
  fixed along the way (not new-code-only — an adversarial pass over the
  whole auth surface caught a pre-existing bug too).

**Still open before this is really "done":** built-in TLS (currently plain
HTTP; use Tailscale/ngrok or your own reverse proxy for anything leaving
your LAN), tunnel start/stop from the CLI (Tailscale/ngrok are still
Settings-only), and — the big one — a genuine live security test against
a real deployment, not just code review.

## Also cooking

- **A dedicated mobile companion app** — a lighter, phone-first way to reach
  your Memo instance, separate from the desktop client.
- **Memo Swarm** continuing to mature out of Beta — pooling multiple
  machines' compute for local inference.
- **Live Mode** getting refined further after its v3.3.4 debut.
- A dedicated feature-parity audit of every desktop/mobile screen against
  a real remote backend — self-hosting only really counts once every
  screen behaves identically to local, and that hasn't been verified yet.

Nothing above is a promise of a ship date or a final feature list — it's a
snapshot of where active work is happening. Check back as v3.5.0 gets
closer.
