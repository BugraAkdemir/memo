# Memo v3.5.5 — Release Notes

> **Open Beta** · August 14, 2026 · [Download](https://memo.bugradev.com)
>
> The self-hosting story that's been building since v3.3.4 is now real: a full 4-mode auth system with per-device tokens, multi-account support, a genuine Flutter-web web UI (replacing the old hand-rolled one), Docker/CasaOS images, and dedicated server-only installers, all managed end-to-end over SSH with `memo config/remote/service/provider/agent/model` — no GUI required, no raw `curl` against the API either. Most of it was hammered into shape on a real Raspberry Pi across several live sessions, not just read in code, and that's exactly how a dozen-plus real onboarding bugs got found and fixed. Also in this release: agent mode (tool use) was silently ignored by non-streaming chat requests and is now fixed, mood is off by default, `--password`/`--key` flags no longer have to be typed in plain sight, and a long tail of smaller fixes throughout.
>
---

## Big Feature: Self-Hosting Is Now a Complete, Real Story

### A Real Auth System, Not a Shared Password

Remote access used to mean one shared token every request compared against. It's now a real system with four selectable modes — no credential, token-only, password, or token+password — with argon2id password hashing, brute-force lockout on login attempts, short-lived signed sessions, and per-device tokens (hashed at rest, shown once at creation, revocable individually without touching anyone else's access). Connecting from the same machine the backend is running on (loopback) never needs a credential at all, in every mode — the desktop app talking to its own local backend was never meant to be gated by the same wall that protects it from the network.

### Multi-Account Support and a Universal Auth Gate

Self-hosted Memo now supports multiple accounts with admin/user roles, managed from Settings → Accounts (add, remove, change password, sign out) — not just a single shared login. Every screen in the app — chat, Settings, Developer Options, and everything else — now goes through the same first-run setup gate and login gate instead of each screen having to remember to check auth state on its own, which is exactly the class of bug (below) that kept resurfacing as new screens got added.

### A Real Web UI — Flutter, Not Hand-Rolled

The built-in web page for headless/CasaOS/browser access used to be a small, separately maintained HTML/JS client. It's been replaced entirely with a real Flutter web build — the same app you'd get on desktop, running in a browser — with working provider setup (add/edit/test a connection), a server-side file browser (for a remote backend where there's no local filesystem to pick from), and model downloads, none of which the old page had.

### Docker/CasaOS, and Dedicated Server-Only Installers

- A multi-arch (amd64 + arm64) Docker image now publishes automatically to GHCR on every push — CasaOS and any other Docker-based home-server setup can pull and run it directly.
- **`get-memo-server.sh`** (and a beta-channel sibling) is a dedicated installer for a machine with no display to show a desktop app on in the first place — same release archives, skips the Flutter desktop binary entirely.
- **`uninstall-selfhosted.sh`** cleanly removes everything a server-only install put down — the systemd service, the binaries, and (with your confirmation, and an optional backup first) the actual data.

### The CLI Grows Into a Complete Management Toolkit

Everything Settings can do to a self-hosted install, `memo` can now do too, over plain SSH:

- `memo config get/set <key>` — edit `config.yaml` directly.
- `memo remote status|list-devices|add-device|revoke-device|rotate-token|set-mode|login` — auth mode and device management. **New this release: `rotate-token`** revokes a device and re-adds it under the same name in one command, for a token that may have leaked and needs to stop working immediately.
- `memo service install|uninstall|status|restart` — a systemd `--user` service with auto-restart, no root needed.
- **New this release — `memo provider list|add|set-active|active`**: configure an external LLM provider (OpenAI, Claude, OpenCode Zen, or any OpenAI-compatible endpoint) without ever touching the REST API by hand.
- **New this release — `memo agent status|enable|disable|auto-permission`**: turn tool-use mode on or off, and toggle the "don't ask before every tool call" auto-permission switch.
- **New this release — `memo model list|status|search|files|download|start|start-embedding`**: search Hugging Face for a GGUF model, download it with a live progress bar right in the terminal, and start it as the chat or embedding model — setting up local memory on a headless box no longer requires a single `curl`.

Run any of these with no arguments for its full usage.

**Security fix bundled in:** `memo remote set-mode`/`login` used to require `--password` as a plain flag value — visible to any other user on the same machine via `ps` or `/proc/<pid>/cmdline`, and left permanently in shell history. Leave `--password` (or the new `memo provider add --key`) off the command line now and it's prompted for interactively with the input hidden, the same way `sudo`/`ssh` ask for a password — and it fails with a clear message instead of hanging if there's no real terminal to prompt on (a script or pipe).

### Found Live, Fixed Live: A Raspberry Pi Testing Marathon

A large share of the bugs in this release were never spotted by reading code — they only showed up running a real backend, on a real Raspberry Pi, reached from a real second device, over several live SSH sessions of install → connect → break something → fix it → reinstall and check again. A representative sample:

- Connecting to a self-hosted backend for the first time could leave chat, Settings, Developer Options, or Routines/Calendar permanently stuck on a generic "something went wrong" — several different screens each had their own one-shot request that gave up for good the moment it happened to land before login finished, instead of retrying once the gate opened. Found and fixed across the whole app, not just the one screen it was first reported on.
- The systemd service Memo's own installer sets up was silently writing real account/memory data outside the directory `uninstall-selfhosted.sh` actually deletes — so an uninstall+reinstall looked clean but quietly kept your old account. Fixed; the service now points at the right data directory.
- The LAN address Memo reported after install could be an unrelated Docker/VPN bridge IP instead of the device's real one. Fixed.
- An ISP-level cache (common in some regions) could keep serving a stale install-script binary indefinitely, even after the real one on the server had already updated — install/update scripts now cache-bust their own download. Found by comparing checksums across three back-to-back reinstalls on the same physical device.
- Deleting a self-hosted server and setting it up fresh could leave the *browser* stuck believing setup was already done, from the previous install, with no obvious way out — the setup gate now recognizes a genuinely fresh install (a new server-side install ID) and clears stale local state instead of trusting it.
- Rate-limit errors from a provider used to show their full raw error text — now translated into a plain, friendly message — and a duplicate error toast that could fire twice for the same failure is gone.
- **The first-run "token-only" setup option 401'd unconditionally** from any device that wasn't the server itself, the whole time — password-based setup was fine, this specific third path never actually worked from a real phone/laptop. Fixed and confirmed live against a real non-loopback client.
- A stray background toast could report "an error occurred in Orchestra" even with Orchestra completely turned off, on any unrelated temporary network hiccup. Silenced.

## Fixed: Agent Mode Was Silently Skipped by Non-Streaming Chat

Sending a message through the plain, non-streaming send path — used when the desktop's Streaming setting is turned off, and directly by `POST /api/send` for any script or integration talking straight to the backend — never actually activated agent (tool-use) mode, no matter whether it was turned on. The model just answered as if it had no tools at all, with no error and nothing to explain why: a request to list files, run a command, or search the web would get a plain, tool-less reply instead. Fixed at the source — that path now routes through the exact same agent-aware pipeline the normal streaming chat already used. A related, independent bug surfaced by testing this fix properly: the record of which tools ran during an agent turn was being captured before the turn had actually finished, so it was silently near-empty regardless of how many tools genuinely ran — also fixed.

## Changed: Mood Is Off by Default

Mood injects a tone directive into every single message when it's on — the same reasoning that already had web search off by default: a feature that changes every reply should be turned on deliberately, not discovered already active. Existing installs are unaffected.

## Small Fixes

- Skills can now be auto-imported straight from Claude Code's own skill directory instead of only being added by hand.
- A skill's activation state now survives a restart instead of silently re-syncing (and potentially reactivating something you'd turned off) on every launch.
- The "backend unreachable" screen now covers every tab consistently, with an inline way to change the server address and a countdown while a restart is expected, instead of only some screens handling it gracefully.
- Raw exception text no longer gets dumped straight into error toasts app-wide.
- Typing a backend address with no `http://`/`https://` scheme no longer crashes the app.
- A CORS origin-validation bypass in the remote-access gate (CWE-346) was found in an adversarial pass over the whole auth surface and closed.

## Security Fixes

- **CORS bypass** in `corsMiddleware`'s origin validation (CWE-346) — closed.
- **Dependency security fix.** `govulncheck` flagged GO-2026-6218, a quadratic-complexity issue in the Go standard library's `net/url` — fixed by bumping the pinned Go toolchain version (`go.mod`) to the patched release.
- **`--password`/`--key` no longer need to be typed as plain command-line arguments** — see the CLI section above.

## Still Open

Carried over from the self-hosting work in this release, honestly not yet done: built-in TLS (plain HTTP for now — use Tailscale/ngrok or your own reverse proxy for anything leaving your LAN), starting/stopping a Tailscale or ngrok tunnel from the CLI (Settings-only for now), and a genuine adversarial security test against a real self-hosted deployment, not just functional testing.
