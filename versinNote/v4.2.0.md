# Memo v4.2.0 — Release Notes

> August 26, 2026 · [Download](https://memo.bugradev.com)
> Web search stops handing back snippets and starts reading the actual page — including the ones that need real JavaScript to render at all.

---

## Big Feature: Web Search Gets Real Page Content, and a Browser to Read the Pages That Need One

v4.1.0 promised a web search rework was coming; this is it. The old `internal/websearch` was a hand-rolled DuckDuckGo HTML scraper — one engine, no fallback, and no way to read anything beyond a link and a snippet. It's now a thin layer over [gosearch](https://github.com/BugraAkdemir/gosearch), with a genuine `fetch_page` agent tool that pulls a result's actual content as Markdown instead of making the model guess from a one-line summary.

Some pages don't hand over their content to a plain HTTP request at all — they need JavaScript to run before there's anything to read. For those, Memo now has a headless-browser fallback (`internal/browserengine`, Chromium via chromedp) that kicks in automatically when a static fetch comes back empty. It's a fully separate browser process from your own Chrome/Chromium — its own profile, its own lifecycle — and Settings now has a toggle for it: install it if it's missing, and choose between spinning up a fresh browser per fetch (lighter on RAM, the default) or keeping one alive across calls (much faster on repeated fetches — roughly 4.3s cold start vs. 1.25s reused). And when a page did need the browser to render, Memo now tells the model that explicitly, so an answer like "this site needed real JS to read" is a stated fact instead of a hedge.

To keep the agent from wandering off to five different unrelated sites chasing one question, `fetch_page` enforces a budget of 5 distinct domains per turn in code, not just by prompting — re-reading a domain already fetched this turn (pagination, another page of the same docs) is free.

## Also in this release

- **Bing dropped as a search engine, DuckDuckGo made the sole one.** Live sessions turned up Bing confidently returning completely unrelated results for Turkish queries — Russian, Chinese, and Arabic pages for football score searches, and it never actually errored, so the DuckDuckGo fallback never even triggered. An honest error now beats a confidently wrong answer.
- **Speech-to-text (whisper) is off by default.** The bundled ~500MB local model was starting unconditionally at every launch and burning RAM whether or not anyone used voice input. A new Settings toggle starts/stops it on demand.
- **Quieter console.** A benign but noisy Riverpod/Element race that flooded the console with harmless errors is now filtered out.
