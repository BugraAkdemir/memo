# Memo v4.3.0 — Release Notes

> August 28, 2026 · [Download](https://memo.bugradev.com)
> Voice mode is now a real-time conversation — you talk over Memo and it stops, it doesn't sit in dead silence while it thinks, and it can run tools or hand work to the main model without dropping out of the call.

---

## Big Feature: Live Mode v2 — a native real-time voice model

The old voice mode was a relay race: your speech went to Whisper, the text to the LLM, the reply back through Piper. Every hop added latency and the model never actually *heard* you — tone, pauses, talking over it, none of it survived transcription.

Live Mode v2 replaces that with a genuine audio-to-audio model. You pick an engine in Settings — **Google Live** (Gemini Live) or **OpenAI Realtime** — paste its API key, choose a voice from the live model list, and the chat's voice button opens a full-screen session that streams both directions at once. The transcript shows up as normal chat bubbles (kept in history, not cleared when the call ends), you can type something mid-call and the live model receives it, and there's a mic mute button that keeps the session up while you're not talking. Live Mode conversations now also feed Memo's long-term memory, the same as typed chat.

Two ways the live model can do real work:

- **Delegate mode** (default) — the live model's only tool is "hand this to the main model." You ask it to search the web or read a file; it says "one sec," Memo's main agent model does the work, and the live model narrates the result back in its own voice. The smaller live model never touches your files directly.
- **Standalone mode** — the live model gets Memo's full agent toolset and runs tool calls itself. Faster and simpler, but it's the one making the calls, so there's a per-session permission policy for it: dangerous tools are asked about **out loud**, and your spoken "yes" / "no" resolves the prompt.

ElevenLabs and Custom engines are wired in too (for the classic discrete path), along with a new speech-to-text layer, engine config with encrypted keys, and a proper engine picker.

## Getting it call-ready

A voice call has no patience for the rough edges a text chat tolerates, so most of this release is real-session polish:

- **You can interrupt it.** Barge-in sensitivity is a Settings choice now — "stop when I start talking" (the default) or "only stop for clear speech" if a noisy room keeps cutting the model off. When you do interrupt, the audio stops *immediately* — the buffered tail is dropped, not played out.
- **It doesn't go silent while it's working.** A delegated task can take real seconds; instead of dead air, the live model keeps you company, and when the result lands it's delivered straight into the session so the model actually speaks it (a plain tool response after the turn ended was being silently swallowed).
- **A long task doesn't strand the call.** If the delegated work runs long, the live model gets a "still working" and the finished answer arrives a few seconds late instead of the whole thing hanging.
- **No more "I can't do that, turn on agent mode."** The live model was being told its tools and web access were off even when they were on. And it now starts in your home directory, so "list the files on my Desktop" just works.
- **Cleaner transcript.** Control tokens and the model occasionally reading its own tool call out loud (`response:delegate_to_main_model{…}`) are stripped before they reach the chat.
- **Continuity.** Toggle Live Mode off and back on in the same chat and it picks up where you left off instead of acting like the conversation just started.

## Also in this release

- **Telegram and WhatsApp reconnect on their own after a reboot.** Both bridges used to make one connection attempt at startup and give up if it failed — and right after a reboot the network usually isn't ready yet, so they'd stay dead until a manual reconnect that often didn't help either. The startup connect now retries with backoff, WhatsApp's auto-reconnect no longer gives up after a couple of minutes, and Telegram's "reconnect" button actually reconnects (with the saved token) instead of just re-checking status.
- **Agent mode survives a backend restart.** It was an in-memory flag that reset to off every launch, so the desktop app's bundled backend would come back with agent mode silently disabled while the UI still showed it on. It's persisted now.
- **No more stale clock from memory.** "What time is it" turns were being saved to long-term memory, so a later time question could pull back the *old* answer. Those turns aren't indexed anymore, and the current-time context is marked authoritative.
- **`run_memo.sh` waits for the backend** before launching the desktop UI, so a slow backend start (compiling, offline network timeouts) no longer greets you with a "can't connect to server" dialog.
