# Memo v4.4.0 — Release Notes

> September 2026 · [Download](https://memo.bugradev.com)
> Hand Memo a checklist and walk away — it plans, works through it step by step, recovers from the errors that would have killed it before, and tells you when it's actually done. Plus a round of work on long coding sessions: less token creep, steadier context, faster local models, and a Code Mode that strips a chat down to just the coding.

---

## Big Feature: The Self-Driving Task Loop

Agent Mode already let Memo read files, run commands, and call tools inside one chat turn. The Self-Driving task loop is what happens when you want it to keep going across *many* turns, unattended, against a real checklist — the difference between "help me with this file" and "here's a `Task.md`, go."

`Task.md` is a plain-Markdown checklist (`- [ ] do the thing`) with optional `# key: value` headers controlling how the loop behaves: which mode it runs in, how chatty its notifications are, whether it's locked to one provider or free to switch on failure, whether it should approve its own plan. Create one by asking Memo directly — it writes the file for you via `create_task_md` — or point the Tasks tab at an existing one.

Two ways to run it:

- **Worker mode** — each item runs as its own turn: do the work, get reviewed, move on.
- **Planner/executor mode** (`# mod: planlayıcı`) — a planning turn first produces a `Plan.md` (steps, acceptance checks, dependencies between them) that you approve before anything executes, either from the Tasks tab's approval card or automatically with `# onay: otomatik`.

For work that's genuinely parallel, an item can split into sub-agents: one write-capable `coder` runs first, then up to three read-only `analyzer`/`reviewer`/`test-runner` sub-agents run at the same time and their findings feed a chief review before the item is marked done.

## A task that fails quietly is worse than one that fails loudly

Most of the hardening in this release is about what happens when something goes wrong mid-task, because the old answer was too often "the task just stops and nobody finds out until they check":

- **A busy chat no longer kills the task.** If the task's chat is mid-turn on something else, the loop queues and retries instead of dying on the spot.
- **Rate limits pause, they don't restart.** A 429 parks the list, waits, and resumes from the exact item it was on — never from the beginning.
- **Transient faults get a real second chance.** A 5xx or a timeout gets an escalating wait-and-retry (5 minutes, then 10) on the same provider before the item is finally parked for you.
- **A bad key doesn't loop forever.** An auth or config fault parks the whole list in a waiting-for-you state instead of retrying something that will never succeed on its own.
- **Every terminal state notifies you** — chat message and push, not just a status flag nobody's watching.
- **You can pause and resume from the chat itself** (`pause_task`/`resume_task`) — whatever you typed while it was paused gets carried into the next step, not dropped.
- **Task lists run in parallel.** Independent lists no longer sit in one queue — they run concurrently up to a configurable cap, and one chat's turn no longer blocks another's, because streaming is now serialised per chat instead of behind a single global lock.
- **Cancel means cancel.** Cancelling a running list used to quietly land on "paused" with a Resume button still offered. It's terminal now — a cancelled list stays cancelled.

## Watching it work

A task running unattended still needs to *feel* watchable:

- **Live activity in the task card** — tool calls, sub-agent turns tagged `[coder]`/`[analyzer]`/etc., and a "model is generating" line during long silent LLM calls instead of a card that just looks frozen.
- **Slow tools announce themselves** before they finish, not just after — a `run_command` that takes 40 seconds doesn't read as a stall.
- **The composer locks while a task runs**, and typing "devam" resumes it — no ambiguity about who's driving.
- **The live card works in the browser now.** On the web build, every streaming endpoint was actually buffering the whole response and handing it over in one shot at the end — so the live task card never rendered, the agent permission dialog only showed up *after* it had already timed out, and chat replies arrived all at once instead of token by token. Web now streams through the browser's own Fetch API. (Desktop was never affected.)

## Long coding sessions without the token creep

An hour-long unattended coding session hits problems a short chat never does — the prompt grows every turn, old context falls off the back, and the same file gets read again and again. A batch of work aimed straight at that:

- **Memory retrieval got real relevance.** The similarity gate was loose enough that it pulled back a near-identical block of memories on *every* query, whatever you asked. It's a real threshold now, scores are recency-weighted, and pinned facts (`/remember`) are ranked against your actual question and capped instead of dumped in wholesale — with near-duplicate facts collapsed. Chat turns now store only what *you* said, not Memo's replies, and fact extraction batches across turns instead of firing once per turn.
- **The turn's context budget scales to your model.** It was a flat 64k regardless of what the model could hold; it's now a share of the real context window (Claude goes from 64k to ~150k).
- **The agent stops re-reading what it already knows.** A per-chat working set tracks which files and commands a session has already touched and feeds a compact digest into the next turn, so the model doesn't burn an iteration rediscovering a file it read two turns ago.
- **Long conversations get condensed, not truncated.** Once history fills most of the budget, the oldest turns collapse into one summary and the recent ones stay verbatim — so the original task statement and early constraints survive instead of silently dropping off the back. The summary is cached, so it doesn't regenerate every turn.
- **Trimmed tool output leaves a marker** instead of vanishing — you can tell when a turn dropped something to fit.
- **A long task finishes instead of stopping at the ceiling.** Agent turns now have a configurable iteration cap and a wall-clock limit, and a task that hits the cap with real progress gets one bounded nudge to keep going rather than halting mid-work.
- **`read_file` handles big files.** It gained offset/limit, the size ceiling went from 1 MB to 25 MB, and a window-less read of a large file auto-limits to the first 2,000 lines with a "lines X–Y of Z" header instead of refusing outright.
- **Anthropic prompt caching.** On Claude, the system prompt and tool schema go as one cached block, so iterations 2..N of an agent turn pay roughly 10% of that static prefix and start faster. Tool order is deterministic now, which is what lets the cache actually hit.

## Minimal Mode is actually minimal now — and local models got faster for everyone

Minimal Mode promised "pure model, zero Memo injection," but three blocks — the clock, the agent working set, the active-skill prompt — were never gated by it. With memory off, a reply that takes ~10 seconds against raw llama.cpp was taking 50s–1min inside Memo.

- **Minimal Mode now strips everything:** persona, mood, clock, working set, skill block, conversation compaction, background intent extraction. With memory already off, a minimal local turn is exactly `[history] + [your message]` — nothing else. On an external provider, no system message is sent at all.
- **Every local-model user got faster, Minimal Mode or not.** The volatile per-turn blocks (clock, working set) moved off the front of the prompt and onto your current message, so the history prefix stays byte-identical between turns. That lets the local llama.cpp server reuse its KV cache instead of re-processing the whole conversation from scratch on every message — which was the entire slowdown.

## Code Mode — a per-chat coding preset

A green code icon in an agent chat's top bar toggles Code Mode: a preset tuned for getting code written, not for conversation. It's on automatically in project and agent chats (with a per-chat override), and forced on for agent turns.

- **Everything a coding turn doesn't need is dropped:** persona, style and passive blocks, personal-memory retrieval, time context, mood, proactive nudges, intent and fact extraction, chat-title generation. In their place, a ~110-token coding directive — read before editing, make targeted edits, match the surrounding style, build and test after non-trivial changes, keep replies short, ask before anything risky.
- **The loop runs longer.** The iteration ceiling goes from 40 to 80 and continuations from 2 to 3, so a bigger job finishes in one pass.
- **Edits flow without a permission prompt.** `write_file` / `edit_file` / `insert_line` / `delete_lines` are auto-approved in Code Mode — every write is snapshotted by the Backup Manager and reversible, and opening a project chat is already consent. The genuinely destructive tools (`delete_file`, `run_command`, `change_directory`) still ask.
- **Net effect per turn:** a ~7k stable, cacheable prefix and zero Memo-triggered side LLM calls — where a normal chat turn can fire up to four, all competing for the single local inference slot.

## Provider tool-calling: Claude and Gemini actually work now

Turns out Agent Mode's tool-calling had a real gap: **Claude and Gemini never supported it at all.** Any agent or task-loop turn on either provider would either fail outright or quietly produce no tool calls, depending on the request shape. Both are fixed now — full request/response translation to each vendor's own wire format, including the fiddly part (batching parallel tool calls into one correctly-shaped follow-up turn, since neither vendor's API works the way OpenAI's does).

Alongside that, a new **Custom (Anthropic-compatible)** provider type joins the existing OpenAI-compatible **Custom** type — for when your own proxy or self-hosted endpoint speaks Anthropic's Messages API shape instead of OpenAI's `/chat/completions`.

## Sharper icons and theme-aware provider logos

- **UI emoji replaced with real icons.** Emoji glyphs standing in for iconography across always-on surfaces (skills, Orchestra, the mood gauge, the engine strip) are now bundled Phosphor / Material SVGs that render identically on every platform. Six settings tabs that shared an icon with another tab got their own glyph.
- **Provider logos follow the theme.** OpenAI's white mark was invisible on a light theme; OpenCode's and xAI's black marks were invisible on a dark one. Monochrome logos are now tinted to the current text colour everywhere they appear. The Kilo icon, which was rendering as a solid black square (an `oklch()` colour flutter_svg can't parse), is fixed.
- **The last hardcoded dialog strings now go through localization** — including a model-search hint that showed Turkish even under the English UI.

## Mobile and touch fixes

- **Content respects the safe area.** On a notched phone, mobile web, or an installed PWA, the chat top bar could render under the status bar and the composer under the home-indicator gesture bar. The shell content is inset now; desktop is unchanged.
- **The model-config dialog scrolls.** Its lower fields and the Start button were unreachable behind the on-screen keyboard on a phone.
- **Rename and delete a chat by long-press.** Those actions were right-click-and-hover only — with no equivalent on a touchscreen, there was no way to rename a chat at all. Long-press opens the same menu now, and the inline buttons have real 32×32 touch targets.

## Also in this release

- **Claude's extended thinking is visible.** Picking an effort level made Claude spend real thinking tokens, but nothing on the backend read the thinking blocks back and the frontend toggle was dead. It's wired end to end for the streaming chat path now.
- **Per-turn token usage is recorded** for agent turns and the Self-Driving internals, so they show up in the stats tab instead of counting as zero.
- **A stopped stream keeps its partial reply** instead of discarding everything generated so far.
- **`get_task_status`** — a new read-only tool plus an anti-fabrication prompt, so the chat model reports real task progress instead of inventing it.
- **Planner/executor mode isolates providers per role**, so the planning turn and the executing turns can run on different providers.
- **`run_command` no longer hangs forever on a process it backgrounds.** Starting a server (`python -m http.server &` and the like) inside an agent turn used to leave the tool call stuck on a pipe that never closed. Output is captured through temp files now, with a bounded wait — the backgrounded process keeps running, the tool call returns.
- **Duplicated tool-call badges in chat, fixed.** A single real tool call rendered as two badges (an executing one and a result one, never collapsed). Adjacent executing→result/error pairs now collapse into one badge showing the final state.
- **The onboarding tour's spotlight overlay was fully opaque** — a first-time user's first screen was a black void with one glowing box. It's translucent now, like an actual spotlight.
- **A failed tool call's activity line now says so** — it used to keep the success-shaped wording with only a small ⚠ glyph; it now leads with "Failed" and the real error reason.
- **`{n} tok`-style placeholders were rendering literally** in a handful of UI strings — a templating gap that only handled `${name}`, not bare `{name}`. Both forms work now.
- **Paid OpenCode Zen models are no longer all labelled "Free".**
- **The read-only `curl` allowlist entry is restricted to localhost.**
