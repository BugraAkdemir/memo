# Memo v4.6.0 — Release Notes

> October 2026 · [Download](https://memocpp.com)
> Memo can now open apps and your browser for you, just by asking — and actually drive the browser it opened, live in a panel next to the chat that you can use with your own hands too. Long answers no longer get cut off halfway, and Memo shows what it is doing every second of a long task. Memory settings got rebuilt end to end — see, edit, and selectively delete exactly what Memo remembers. The same app now runs on Android and iOS, Usage Stats show what prompt caching saves you, and a new Subscriptions page lets you sign in once with your Antigravity, Claude or Codex account instead of using an API key — with the remaining allowance shown next to every model. A new free-friendly provider (Cline) joins a redesigned Add Provider flow built around finding a $0 model in one click.

---

## Big Feature: Memo can open apps for you

Ask Memo to open something — "Spotify'ı aç", "Steam'i başlat", "tarayıcıyı aç" — and it now actually launches it, on Windows, macOS, and Linux alike. This is the first layer of a longer computer-use roadmap: today it's launching a named desktop app or your default browser; controlling what happens inside that app (playing a specific song, opening a specific page) is a separate, future step.

"Browser" and its common Turkish/English variants open a blank tab directly. Any other name is handed to the OS's own way of launching an app by name — the same thing typing it into a terminal would do. Launching an app is a real action with a real side effect, so it goes through Memo's permission system like every other agent tool, just one notch lighter than a shell command.

Care went into making sure Memo doesn't reach for this by mistake: a question like "en son haberler ne" should trigger a web search, not open a browser, and the tool descriptions Memo reads are written specifically to keep that boundary clear.

## Big Feature: A live, interactive browser panel

Memo no longer just reads a web page — it can go in and navigate it. A new browser panel that opens next to the chat shows, live, a real but fully isolated Chromium tab that Memo drives (separate from your own browser, never touching your accounts): go to a site, click a button, type into a form, scroll — with a screenshot refreshed after every step, streaming in front of you as it happens.

The panel works both ways. Memo can drive it with its own tools (navigate, click, type, scroll, take a screenshot) — for example to actually test a web page it just wrote. Or you can drive it directly: type an address into the bar at the top (no need for `https://`), click on the screenshot to click the same spot on the real page, and click a field then type into it from the row underneath; Agent Mode doesn't even need to be on for that. The panel can be resized by dragging, and goes full width on narrow (phone-width) screens.

There are a few real fixes behind it: Memo no longer guesses a CSS selector blindly to click a button — it first lists every clickable element on the page with a real, guaranteed-to-work selector, then clicks that. Screenshots now stream only to the live panel and never enter the chat history, so they don't bloat the model's own memory (or your token bill) — understanding what the page says goes through a separate, text-based reading path. And a plain read request like "summarize this site" still goes down the fast, ordinary page-fetch path; the slow, interactive browser only kicks in when clicking/typing is genuinely needed or explicitly asked for.

## Big Feature: Long tasks no longer get cut off — and you always see what's happening

A long answer in plain chat used to hit a fixed 300-second total limit: even while the answer was still flowing, it was cut at exactly the 300th second and saved as "⏹️ Cevap durduruldu." as if you had stopped it. A long conversation (a big history, a slow local model) reached that limit easily. An answer is now ended by **silence**, not length: 300 seconds with nothing arriving (waiting for the first word included), or a 30-minute safety cap. An answer that ends this way is clearly marked as a ⏱️ timeout, and the text received up to that point is kept. In testing, an answer that streamed word by word for 350 seconds completed without being cut.

The UI no longer leaves "is it stuck or still working?" unanswered either. While a turn runs, a live progress line at the bottom shows the current phase and an elapsed timer that ticks every second ("The model is thinking · 0:45"), and it no longer looks frozen after a tool finishes. If nothing at all arrives from the server for 30 seconds, the line turns into an orange "no word from the server" warning. The server, for its part, sends a small "still here" signal every 10 seconds it stays quiet, so a long, silent thinking phase is not mistaken for a dropped connection.

## Big Feature: Subscriptions — use your Antigravity, Claude and Codex accounts in Memo

Sign in once under **Settings › Subscriptions** and every model your account offers shows up in Memo: in the chat's model selector (top right), in the `/model` command of the terminal client, and on the local gateway (`localhost:8090/v1`, model names like `subs/claude-sonnet-4-6`). No API key, nothing to register.

- **One sign-in per vendor.** Antigravity (Claude and Gemini 3 models and more, on the quota your Antigravity account has), Claude and Codex. The browser opens, you sign in, you are done; the account's email is shown and you can sign out any time.
- **All models, picked where you chat.** The list comes from the account itself, grouped by vendor — nothing is hand-written, so new models appear without an update. Pick one in the top-right selector or with `/model`; Memo switches model and provider in one step.
- **A model picker built for long lists.** The top-right selector is now a panel instead of a plain menu: it never runs off the bottom of the window, scrolls inside, searches once there are more than seven rows, and folds each vendor's models under a collapsible heading. Models get readable names ("Gemini 3.7 Flash" with a small "High" tag) and the logo of their model family; what is stored and sent is still the raw model id. The model you pick stays selected after a restart.
- **See how much allowance is left.** Each model shows a remaining-percentage badge and the time until it refills. Antigravity reports it per model; Codex and Claude meter the whole account in time windows (Claude: 5-hour and 7-day), so the tightest window is shown on all of that vendor's models. The figures refresh in the background and never hold the menu up — opening the picker no longer freezes Memo while a vendor answers.
- **When the allowance runs out, Memo tells you and carries on by itself.** A chat turn that fails because the usage limit was reached now leaves a card in the chat with a countdown to the refill, a "Continue automatically when it resets" checkbox (on by default, remembered), and a "Continue now" button. When the time comes Memo types "continue" into that chat for you. Once an allowance drops to 10% or less, a small warning appears — once per allowance window. This works while Memo is open; the card is not kept after you close the app. Task-loop runs already park a task and retry on their own timer, and CLI-agent chats and WhatsApp replies do not show the card.
- **Draw and edit pictures with the same accounts.** Image models of a subscription (for example Codex's) generate an image from text, or edit a picture you attach. Which models draw is read from the endpoint itself, not guessed from the model name, so new image models work without an update. Antigravity's own image model is recognised too, but Google currently answers it with an error on the account it was tried with, so a successful picture from it is not confirmed.
- **Your chosen model survives a restart again.** The helper lists its models vendor by vendor while it warms up; a restart could see only the Codex ones, decide your earlier Claude pick was gone, and fall back to the first model it saw — an image model, so the next message drew a picture. Memo now waits while a signed-in vendor has not listed anything yet, and the fallback never picks an image model.
- **Sign-in and model-list fixes.** The sign-in page now opens reliably (it failed with a relative data folder and under KDE), and the model list that arrives about 30 seconds after signing in is picked up instead of the empty first answer being kept until a restart.
- **Nothing is downloaded behind your back.** The helper that talks to the vendors (CLIProxyAPI) ships inside Memo, checked against a pinned checksum at build time and again at launch. It listens only on your own machine, with a random key.
- **Replaces the old Gemini and Claude subscription features.** Those carried their own sign-in code that vendors kept breaking (Google closed the client Memo used for personal accounts). They are gone; a leftover old entry in your provider list is removed on the first start, and their stored tokens are deleted.
- **A note on risk.** These accounts are used through a third-party client. The vendors may not allow that and could restrict an account — the Subscriptions page says so, and it is your call.

## Big Feature: The context ring — see how full the window is, and Memo compacts it for you

A small ring at the foot of the chat (in the engine strip) shows how full the model's context window is. Tap it and a popover opens, like the one in Claude Code: how much is used out of the window (`325.1k / 1M (33%)`), a segmented bar, and a row for each part — your messages, an earlier conversation Memo summarized, the system prompt, memory, skills, the tool definitions, the new message — then the free space and the slice held back so auto-compact can run. The ring turns amber and then red as it nears the compact point.

- **Real numbers when the provider gives them.** The size is the provider's own prompt-plus-reply token count when it reported one; the parts are scaled to add up to it. When it did not, the figure is an estimate and is marked with `~` and says so.
- **Your Subscriptions limits, in the same place.** For a Subscriptions model the popover also lists the account's usage meters: the 5-hour *session* limit and the *weekly* one for Codex and Claude, the model's own figure for Antigravity, each with how long until it refills.
- **Memo summarizes older turns at 90%, on every provider.** Local model, API provider or Subscriptions: once the whole prompt — system prompt, tool schema, history and your new message — reaches 90% of the model's window, the oldest turns are condensed into a summary and the recent ones stay verbatim. It also fires when the provider's own count from the previous turn is already there, which catches what a word-count estimate under-counts (Turkish, code). The popover says how many messages a summary currently stands in for. Before this, compaction measured the history alone at 60% of a reduced budget.
- **An agent turn no longer overshoots the window.** The tool definitions travel alongside the messages and are real context; API providers' history budget ignored them, so a long agent chat could send a request larger than the window. They are now taken off the history's share.

## Big Feature: Errors you can read

A failed request used to land in the chat as `⚠️ [custom] status 400: Your request was rejected by the safety system … request ID … safety_violations=[sexual]`. Provider failures are now explained in a sentence, in your language, with the HTTP status as a small tag: a safety refusal ("the provider's safety filter refused this request — try rewording it or pick another model"), a used-up allowance, a rate limit, a wrong or expired key (and, for Subscriptions, "sign in again"), a forbidden model, an unknown model, a conversation too long for the window, a timeout, a provider that is down, no network, and any other refused request. It applies to every provider and every kind of turn, on the app, the terminal client and WhatsApp; the original text is kept in the log.

## Big Feature: Telegram and WhatsApp can switch models, send pictures and draw them

The chat bots could only exchange text with a fixed model. Now:

- **`/model` switches the model from the chat.** It lists every model one message away — each provider's model, every live model of your Subscriptions accounts grouped by vendor, the local one — numbered, with the active one and the image models marked. `/model 3`, `/model gemini` or `/model <provider> <model>` switches.
- **Send a photo.** Memo describes it; caption it with a change ("make it black and white") and it edits it. Ask for a picture in words ("draw me a cat") and one is drawn and sent back as a photo. `/image <what to draw>` forces a picture whatever the wording.
- **Pictures are drawn by the right model on their own.** Asking any chat — in the app, the terminal, Telegram or WhatsApp — for a picture sends that one message to an image model, and the next message is answered by your text model again; nothing is switched. On a Subscriptions account the picture is drawn by that account's own image model (a Codex chat uses Codex's, an Antigravity chat Antigravity's), never the default. Every other provider uses a **default image model** you choose under Settings › API Providers › Image generation (there is also a switch to turn the routing off).
- **Errors you can read in the chat too.** A 400, 404, 429 or 500 reaches Telegram and WhatsApp as a sentence about what happened and what to do, not a provider status dump — and the same now holds for the non-streaming endpoints and Live Mode.
- **A picture with no caption is no longer dropped by WhatsApp.**

Verified end to end against a fake Telegram Bot API; not yet against the real Telegram and WhatsApp apps.

## Big Feature: Android and iOS — one app, everywhere

The separately maintained mobile client has been retired; the same Memo app you use on desktop and the web now builds for Android and iOS too. The phone runs as a client that connects to the Memo server you host:

- **A server-address step on first launch.** There's no local server on a phone to guess at, so the setup wizard now asks for the address first (and a token, if you use one) and tests the connection before saving. Tailscale Funnel addresses (`*.ts.net`) automatically open over `https`, with no port appended.
- **Calendar reminders arrive as the phone's own notifications**, even when the app isn't open.
- **Spoken replies and sounds play on the phone.**
- **On Android, the back button no longer exits the app**: it closes an open menu first, then returns to chat. The system bars follow the light/dark theme.
- Desktop-only actions that mean nothing on a phone (such as the CLI install) are hidden.
- Builds: a signed APK for Android and an unsigned IPA for iOS (installing it requires signing it yourself or sideloading).

## Big Feature: Memory settings, rebuilt

The Memory tab in Settings could tell you *how* memory retrieval was configured, but not *what* Memo actually remembers — and there was no way to fix a wrong memory without clearing everything. This release closes both gaps:

- **See what Memo knows about you.** A new, always-visible list shows every fact Memo has pinned about you — read-only, for peace of mind, not fed back into any prompt beyond what already happens automatically.
- **Edit or delete exactly what's wrong**, one fact at a time or several at once, with checkboxes and a select-all/deselect-all bar. A separate, identically-equipped list handles your ordinary (non-pinned) conversation history — keep your pinned facts while clearing chat history, or the reverse, entirely independently. Every delete — one row or a whole selection — asks for confirmation first and shows exactly how many records it removed.
- **A properly organized tab instead of one long scroll.** Retrieval settings, memory files, usage analytics, known facts, conversation history, and debug search used to stack on top of each other in a single page — reaching the last section meant scrolling past everything else. They're now five focused sections switched with a pill bar at the top, each showing a live count before you even open it. The General settings tab got the same treatment, split into General, Features, Reset, and CLI & Uninstall.
- **Dream — the background pass that compresses old, related pinned facts into cleaner summaries — actually runs now.** It quietly wasn't: a wiring gap left it permanently dormant on a fresh launch unless you happened to trigger an unrelated action first, with no indication in the UI that anything was wrong. Fixed at the source; Dream now activates the moment Memo starts.

## New Feature: Cline joins as a provider, and Add Provider gets easier to navigate

**Cline** is now a supported external LLM provider — same one-click setup as every other provider, its own logo in the picker, and (like OpenRouter/Kilo/OpenCode Zen) a real per-model free/paid catalog instead of a bare model-ID list.

The bigger change is to Add Provider itself: with fourteen options in a flat list, there was previously no signal at all about which ones cost nothing to try. Providers with a genuine free tier now show a green badge and sit in their own group, separate from paid providers — and for the four providers with a real free-model catalog, a new **"Pick a free model"** button picks a working $0 model for you in one click, no understanding of pricing or model-ID syntax required.

## New Feature: Prompt caching is now measured

Memo already used prompt caching on the providers that support it (repeated system and tool definitions billed at a discount on every turn), but there was no way to see what it saved. Settings › Usage Stats now has a **Prompt Cache** panel: how much of your input was read from cache, how much was written to it, and how much went at full price, the share served from cache, and "N cached" badges on the per-model and per-category breakdowns.

A few things were fixed to make that possible:

- **Streaming chat now uses the provider's real token counts.** Plain chat used to estimate from word count, which could not carry any cache information.
- **On Anthropic, input looked *smaller* the better the cache performed**, because Anthropic reports cached tokens separately. It is now added up correctly.
- **Custom Anthropic-compatible endpoints (proxies) now get prompt caching too.** It used to be enabled only for `api.anthropic.com`. An endpoint that doesn't support it notices on a single request and switches it off for the session.
- For a provider that reports nothing, the screen says "not reported" instead of showing a measured 0%.
- The developer gateway (`/v1`) also reports the cache split to its own clients correctly; it could previously make a cached agent turn look ~10x more expensive.

## New Feature: Image-generation models (OpenRouter)

Selecting an image-only model on OpenRouter broke every turn: the request went to the chat endpoint, got a 404, and the chat showed "all providers failed". These models are now routed to OpenRouter's image endpoint, and the generated image arrives in the chat as the reply. Which models are image models is read from OpenRouter's own catalog, not guessed from the model name. Background jobs that need text — chat titles, memory extraction — no longer call these models at all.

## Small feature: open pictures full-window

Tap a picture in the chat (or its enlarge button) to zoom with the buttons, the mouse wheel, pinch, double-tap or the `+` / `-` / `0` keys, pan while zoomed, see its details (resolution, aspect ratio, format, size), and download it.

## Small feature: Skills are now active only in the chat you turn them on in

Turning a skill on in one chat used to leave it active forever in *every* chat you opened from then on — there was no way to turn it off, and old skills imported in the past could still be running without you knowing. Activation is now entirely per chat: turn a skill on in one chat and it only works there; every new chat starts with it off. Settings › Skills now only lists installed skills (install/uninstall) — turning one on or off happens inside the chat you want to use it in.

## Small feature: see which other chats are still working

Running several conversations at once — a task in the background, a WhatsApp or Telegram reply, a second browser tab open to the same Memo — used to leave the sidebar showing nothing for any chat you weren't actively looking at, even while it was still generating a reply. Every chat that's actually working now shows the same small spinner (and a "just finished" indicator right after) the sidebar already used for Claude Code/Codex sessions — extended to cover every kind of chat, not just those.

## Reliability pass

- **Memo no longer goes completely silent on a turn.** A model that produces no tool call and no text — a weak or local model, a request nothing in the current tool set fits — used to end the turn with literally nothing shown, indistinguishable from a dropped request. It now always leaves you with a real, visible message instead of dead air.
- **Telegram and WhatsApp now correctly prefer what you just told Memo over an old conversation summary.** Long-running chats on those channels occasionally condense their oldest messages into a background summary for context-budget reasons — accurate for what was true *at the time*, but with no signal telling the model which one wins if it conflicts with a fact you pinned since. Memo's prompt now says so explicitly.
- **Attaching a file or image from the web (connecting to a self-hosted Memo from a browser) silently did nothing** — no preview, no error, no upload. Desktop was fine. The root cause is fixed; attaching files and images now works on the web too.
- **Instead of saying it can't do something with Agent Mode off and stopping there, Memo now suggests turning on Agent Mode (or web search) and carries on** — and it now says so explicitly for requests involving the new browser feature, where it previously just said "it's off" and moved on.
- **While an autonomous (Self-Driving) task is running, asking "how's the task going" or "where did it get to" in chat now makes Memo read and report the real status** instead of guessing — and multiple autonomous tasks bound to the same chat can no longer have their progress mixed up.
- **A provider whose API key is invalid or expired no longer wrongly shows as "connected" in Settings** — the real error now surfaces correctly.
- **Claude Opus 4.7 and later now work.** These models reject sampling settings such as `temperature`, and every request got a 400 error. Memo now notices the refusal once and stops sending it for that provider.
- **With thinking on, Claude's agent-mode tool loop used to break**; thinking blocks are now sent back correctly between tool turns.
- **Your only active provider no longer gets locked out for 5 minutes after three errors.** Backing off only makes sense when there is another provider to fall back to; with a single provider it just silenced Memo for 5 minutes.
- **An answer cut off halfway is no longer lost** — what arrived up to that point is saved — and an empty answer no longer stays as an unexplained empty bubble. An empty "finish reason" sent by some providers is no longer taken to mean "finished".
- **Images you send no longer disappear, and they show up on the web and on phones too.** Images are now stored on the server and served from there; before, only the desktop app on the same machine as the server could see them.
- **The right chat across multiple devices.** Reading, editing, and deleting messages now applies to the chat you selected, not to whichever chat happens to be open on another device at that moment.
- **A message sent right after an answer no longer gets "please wait until the previous response finishes".** The chat's lock was released slightly late when an answer finished, and a quick next message could land in that gap.
- **The automatic chat title no longer overwrites a name you gave the chat.**
- **"Remember this" now works on every setup.** On a cloud-only setup with no embedding model, saving an explicit memory failed silently.
- **Routines:** a schedule that can never fire is no longer accepted, and a routine already saved with one can now be switched off.
- **Calendar:** the default view starts at local midnight, and events without a title are no longer accepted.
- An empty message no longer spends a model turn. "Restart Memo" now works in the web version. Idle chats no longer look busy because of a background check.
- A handful of Settings screens (API Providers, Backup & Restore, Learning, Usage Stats, and Memory's own selection toolbar) had a title or label that could crowd against a button under long Turkish text at narrow window widths — audited and fixed across the board.

## Security

- **Pictures are encrypted on disk.** Every image you send Memo and every image Memo draws is stored as ciphertext (XChaCha20-Poly1305, a fresh key per file, authenticated), so copying, backing up or leaking the data folder does not expose them. The master key is deliberately outside the data folder (`~/.config/Memo/image.key`, or a passphrase in `MEMO_IMAGE_KEY`). Pictures from earlier versions are sealed once at startup; nothing in the app looks different. What cannot be protected: a picture while it is open in memory, and the copy a model provider, Telegram or WhatsApp receives when it is sent there.
- A transitive dependency (`google.golang.org/grpc`, pulled in indirectly through cloud/auth libraries — nothing in Memo calls it directly) carried a flagged HTTP/2 memory-exhaustion vulnerability (GO-2026-6348). Bumped to the patched version; nothing else changed.
- Several security and stability gaps found in an internal audit were closed in some of the agent tools (the tool that copies a project to another location, the sub-agents autonomous tasks run in the background, and the WhatsApp integration) — none was exploited in the wild; they were found in a routine security scan and fixed in the same session.
- **Multi-account remote access: an unprivileged account could perform admin actions.** A regular `user` account could shut Memo down, wipe its data, import and uninstall, and download a full backup including the encryption key. It could also read every API key, the gateway token, and the new-device token. These actions are now admin-only, and secret values are hidden from accounts without the permission. Single-user desktop setups were not affected.
- **Incognito mode wrote to disk for messages sent to a specific chat.** Since that is exactly how the app itself sends messages, incognito was in practice not doing its job; fixed.
- **The interactive browser could read any file on the machine through `file://` addresses**, which let it bypass the agent's file-reading restrictions entirely. Only `http`, `https`, and a blank page are accepted now. The endpoints that drive the browser session now also require agent (tool-execution) permission.
- When a web page is fetched, the log now records a short preview instead of the whole page.

## Packaging

- **The AppImage now meets the AppImage catalog's requirements.** The file is now named `Memo-v<version>-x86_64.AppImage` and carries AppStream metadata (`com.memocpp.Memo`) and desktop-entry metadata. The AppImage is now also attached to GitHub Releases on every version.
- **The AppImage has its own download channels, like the tar.gz.** A version tag publishes it as `memo.AppImage` on `data.memocpp.com`; every push to `main` publishes the current build as `memo_beta.AppImage`. Builds that are not a tagged release no longer end up with a doubled "v" in the file name (`Memo-vV4.6.0-…`).
- **Linux x86_64 only for now.** The ARM64 build still ships as a zip.
