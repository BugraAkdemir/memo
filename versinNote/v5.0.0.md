# Memo v5.0.0 — Release Notes

> October 19, 2026 · [Download](https://memocpp.com)
> Memo now understands **Projects**. Open a folder and it can keep its own working rules and notes there and give that project a memory of its own — while your personal memory, your name and your style notes never reach a project. This release also merges the two chat lists into one with a new "Chat | Agent" start screen, lets you watch the agent work as it happens, and lets the terminal and the desktop app run side by side.

---

## Big Feature: Projects

When you pick a folder for an agent chat, Memo asks once: **"Set up Memo for this project?"** — *Set up*, *Not now* or *Never for this folder*. Nothing is written unless you answer *Set up*.

- **What gets created.** A small `.memo/` folder (generic working rules, a notes file, project settings) and, in the project root, an `AGENTS.md` and a `handoff.md` — never over a file you already have, and no second `AGENTS.md` next to your `CLAUDE.md`. The rules are about quality and are the same for every language and framework: understand before changing, fix root causes, keep the change small, never say "done" without running the project's real checks, say what you did *not* verify, don't commit unless asked.
- **The model reads them when it needs them.** A one-line instruction tells it to read `.memo/AGENTS.md` first. The files are not pasted into every prompt, so prompts stay small.
- **A memory of its own.** A project chat reads and writes only **its own project's** memory. An ordinary chat still sees everything. A project chat **never** receives your general memory, your pinned facts, your name, your learned style notes or your custom persona — a client project doesn't need to know who you are. This holds with Code Mode on or off. The memory follows the folder if you move or rename it; a copied folder gets its own.
- **Your home folder can never be a project.** Memo's own install lives in `~/.memo`, which has the same name as a project's folder, so Memo refuses your home folder, Memo's own folders and system folders, and never writes into a `.memo` it didn't create.
- **Project skills.** Add a skill to one project with `/skill add owner/repo` (or by pasting the `npx skills add …` line from its README, or asking the agent). Memo reads the source out of the line and downloads plain files — it never runs `npx` or anything else. A project skill is instructions only (the tools it declares are ignored) and stays out of the prompt until you switch it on with `/skill:on`.
- **Minimal Mode stays a pure wrapper:** no setup question, no instruction, nothing read. Self-Driving tasks with "task memory" off neither read nor write project memory.

## Big Change: One chat list, and a new start screen

- The separate **Agent** tab is gone. There is one chat list; an agent chat is a chat with a project folder and is marked with a robot icon. The Code Mode switch and the Tasks button live in the chat's top bar for agent chats.
- A new chat starts on a new screen: a **Chat | Agent** switch, a centred composer with the model picker, and starter suggestions. You choose Chat or Agent before the first message and it stays that way. The composer drops to the bottom after you send.
- A blank chat is listed first, and *New Chat* reopens it instead of piling up empty chats. Agent chats get a title from your first words.

## Agent: you see the work as it happens

- **Live.** The agent loop now streams: the model's text next to its tool calls ("I'll check the config first"), its thinking and each tool call appear in order as they happen, instead of a spinner and then a wall at the end. Tool calls are grouped ("Ran 3 commands") and open to show what ran.
- **Long turns no longer lose the task.** A long coding turn used to crash with a context-size error after dozens of steps, and before that forgot your request while keeping the newest tool output. Memo now keeps your request and the earlier conversation, replaces old tool output with a one-line stub when the budget is reached, and measures a long conversation against a sensible ceiling instead of a 1M-token window.
- **No more giving up on an empty step.** If the model returns nothing after using tools, Memo nudges it to answer from what it found before showing "couldn't generate a reply". Models that stay silent between tool calls are asked to say what they are doing.

## Terminal: use it next to the desktop app

- The terminal chat's settings (auto-permission, web tools) now belong to that terminal session only, and opening a chat there no longer moves the desktop app's open chat. Two clients can share one Memo.
- It shows thinking, the model's words and every tool call live, and leaves one line per finished call (what ran, how long, or the error).
- Typing `/` lists Memo's commands and the installed skills with their on/off state; `/skill` lists and toggles them for that chat.

## Improvements

- **A folder and file picker you can use:** paste or type a path (`~` works), filter as you type, hidden folders are off by default (with a toggle), recent folders as chips.
- The agent chat's top bar has the **model and reasoning-effort pickers** the plain chat has.
- Fixed: picking a file from the `@` list with Tab dropped the keyboard; the list now keeps your selection in view and mentions show in blue.
- Fixed: the new-chat composer's bottom row is flush (send at the edge, model button beside it).

## Good to know

- **Everyone gets the setup question once per project folder.** Say *Never for this folder* to stop it for that folder.
- **One-time database change.** Memory gets one new column. Before touching a database that has memories, Memo saves a full copy to `data/backups/memory-pre-project-id-….db` (it stays on your machine and is not part of exports or cloud sync). If that copy can't be written, the change is skipped: normal chats work exactly as before and project chats have no memory until the next start. An older Memo can still read the upgraded memory file.
- **Not yet done:** per-project command permissions (the "always allow `go test` in this project" list). There is also no skill picker in the app yet — use `/skill`, `/skill:on` and `/skill add`.
- **Not yet verified on real machines:** the setup window on a real desktop, downloading a skill from real GitHub (only a local stand-in server was used), a real model's habit of following the "read `.memo/AGENTS.md` first" instruction, and the memory upgrade on a large real database (it was tried on a sample database with the old layout).
- **The agent's live view was tested with fake providers and widget tests, not yet against every real provider.**
